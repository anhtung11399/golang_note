HTTP từ gốc với net/http

HTTP nhìn từ phía máy chủ, viết server bằng thư viện chuẩn, định tuyến kiểu Go 1.22, đọc và trả JSON an toàn.

Học xong bài này bạn sẽ:
  • Viết server JSON không cần framework
  • Đọc tham số đường dẫn, query, body
  • Đặt timeout và giới hạn kích thước request

#HTTP nhìn từ phía máy chủ

Ở frontend bạn gửi request bằng fetch và nhận một object Response đã được trình duyệt dọn sẵn. Thật ra trên đường truyền, HTTP/1.1 chỉ là văn bản:

Request client gửi lên
POST /api/classes/5/assignments?notify=1 HTTP/1.1
Host: api.sobaitap.vn
Content-Type: application/json
Cookie: session=6f1c...
Content-Length: 58

{"title":"Bài 3 trang 12","dueDate":"2026-11-10","count":3}
Response máy chủ trả về
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/assignments/9001

{"id":9001,"title":"Bài 3 trang 12","dueDate":"2026-11-10"}

Việc của backend là đọc từng phần của request (method, đường dẫn, query, header, cookie, body), quyết định và viết ra từng phần của response (status, header, body). HTTP/2 và HTTP/3 truyền dạng nhị phân, nhưng các phần này vẫn y nguyên, và Go xử lý chúng giúp bạn.

#Server nhỏ nhất

main.go
package main

import (
    "fmt"
    "log"
    "net/http"
)

func main() {
    http.HandleFunc("GET /hello", func(w http.ResponseWriter, r *http.Request) {
        name := r.URL.Query().Get("name")
        if name == "" {
            name = "bạn"
        }
        fmt.Fprintf(w, "Xin chào, %s!", name)
    })
    log.Println("chạy ở http://localhost:8080")
    log.Fatal(http.ListenAndServe(":8080", nil))
}

Chạy thử: cần hai cửa sổ terminal

Khác các chương trình trước (chạy xong là thoát), server chạy mãi để chờ request. Vì vậy:

Terminal 1: tạo dự án như bài 01 (mkdir hello-http && cd hello-http && go mod init hello-http), dán code vào main.go, rồi chạy. Terminal này sẽ "đứng yên", đó là đúng:

Terminal — kết quả khi chạy
$ go run .
2026/11/03 09:00:00 chạy ở http://localhost:8080

Terminal 2 (mở thêm một tab terminal mới): gửi request bằng curl, công cụ gửi HTTP từ dòng lệnh có sẵn trên macOS và Linux:

Terminal — kết quả khi chạy
$ curl "localhost:8080/hello?name=Lan"
Xin chào, Lan!
$ curl localhost:8080/hello
Xin chào, bạn!
$ curl -X POST localhost:8080/hello
Method Not Allowed

Hoặc mở trình duyệt vào http://localhost:8080/hello?name=Lan, trình duyệt cũng chỉ gửi một request GET. Request POST bị từ chối vì đường dẫn đăng ký là "GET /hello": Go tự trả 405 Method Not Allowed.

Muốn tắt server: quay lại terminal 1, bấm Ctrl + C. Sửa code xong phải tắt rồi go run . lại (Go không tự tải lại như vite dev).

Gặp lỗi listen tcp :8080: bind: address already in use nghĩa là đang có chương trình khác (thường là chính server cũ bạn quên tắt) chiếm cổng 8080. Tắt nó đi, hoặc đổi ":8080" thành ":8081".

Đọc từng dòng

  • http.HandleFunc("GET /hello", func(w, r) {...}): "khi có request GET tới /hello, chạy hàm này". Giống app.get("/hello", (req, res) => {...}) của Express.
  • r.URL.Query().Get("name"): lấy tham số ?name= trên URL. Không có thì ra chuỗi rỗng.
  • fmt.Fprintf(w, ...): giống Printf nhưng ghi vào w (response gửi về client) thay vì màn hình.
  • http.ListenAndServe(":8080", nil): mở cổng 8080 và bắt đầu nhận request. Hàm này chạy mãi, chỉ trả về khi có lỗi. log.Fatal in lỗi đó rồi thoát.

Hai nhân vật chính:

  • r *http.Request: mọi thứ client gửi lên. r.Method, r.URL.Path, r.URL.Query(), r.Header, r.Body, r.Context().
  • w http.ResponseWriter: nơi bạn viết response. w.Header().Set(...), w.WriteHeader(status), w.Write(body).

#Handler: một interface một method

Mọi thứ trong net/http xoay quanh interface này:

Go · trích đoạn
type Handler interface {
    ServeHTTP(ResponseWriter, *Request)
}

Bộ định tuyến (ServeMux) là một Handler. Middleware là hàm nhận Handler và trả về Handler. Ứng dụng của bạn là một Handler. Toàn bộ hệ sinh thái HTTP của Go ghép với nhau được nhờ interface này.

#Định tuyến kiểu Go 1.22

Từ Go 1.22, ServeMux của thư viện chuẩn hỗ trợ method và tham số đường dẫn, đủ cho đa số API mà không cần framework:

Go · trích đoạn
mux := http.NewServeMux()

mux.HandleFunc("GET /classes", listClasses)
mux.HandleFunc("POST /classes", createClass)
mux.HandleFunc("GET /classes/{id}", getClass)
mux.HandleFunc("PATCH /classes/{id}", updateClass)
mux.HandleFunc("GET /classes/{id}/assignments", listAssignments)
mux.HandleFunc("GET /files/{path...}", serveFile) // {path...} khớp phần còn lại, kể cả dấu /
mux.HandleFunc("GET /{$}", home)                  // {$}: chỉ khớp đúng "/", không khớp mọi đường dẫn

func getClass(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
    if err != nil {
        http.Error(w, "id không hợp lệ", http.StatusBadRequest)
        return
    }
    // ...
}
  • Mẫu cụ thể hơn thắng: GET /classes/new thắng GET /classes/{id} khi đường dẫn là /classes/new.
  • Đường dẫn đúng nhưng sai method → Go tự trả 405 kèm header Allow.
  • Mẫu GET cũng khớp HEAD.

Trước Go 1.22, gần như ai cũng phải dùng thư viện router: gorilla/mux, go-chi/chi, hoặc framework gin, echo. Bạn vẫn sẽ gặp chúng rất nhiều trong code công ty. Tin tốt: chi dùng đúng kiểu http.Handler chuẩn, nên những gì bạn học ở đây dùng y nguyên. gin và echo có kiểu context riêng (*gin.Context), cú pháp khác chút nhưng khái niệm giống hệt.

#Đọc JSON an toàn

Đọc body là chỗ người mới hay để lỗ hổng. Một client xấu có thể gửi body 10GB, JSON lồng sâu, hay trường lạ. Hàm đọc JSON chuẩn nên trông như sau:

internal/httpx/json.go · trích đoạn
const maxBody = 1 << 20 // 1 MB

func DecodeJSON(w http.ResponseWriter, r *http.Request, dst any) error {
    if ct := r.Header.Get("Content-Type"); !strings.HasPrefix(ct, "application/json") {
        return &ValidationError{Field: "body", Message: "Cần Content-Type: application/json"}
    }
    r.Body = http.MaxBytesReader(w, r.Body, maxBody) // chặn body quá lớn
    dec := json.NewDecoder(r.Body)
    dec.DisallowUnknownFields() // trường lạ → lỗi, bắt được lỗi gõ sai tên trường

    if err := dec.Decode(dst); err != nil {
        var tooBig *http.MaxBytesError
        if errors.As(err, &tooBig) {
            return &ValidationError{Field: "body", Message: "Dữ liệu quá lớn"}
        }
        return &ValidationError{Field: "body", Message: "JSON không hợp lệ"}
    }
    if dec.More() { // còn dữ liệu sau object đầu tiên: {"a":1}{"b":2}
        return &ValidationError{Field: "body", Message: "Chỉ gửi một object JSON"}
    }
    return nil
}

#Trả JSON đúng thứ tự

Go · trích đoạn
func WriteJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8") // 1. header
    w.WriteHeader(status)                                             // 2. status
    if err := json.NewEncoder(w).Encode(v); err != nil {              // 3. body
        slog.Error("ghi JSON", "err", err)
    }
}

Thứ tự bắt buộc: header → status → body. Gọi w.Write trước WriteHeader thì Go tự gửi status 200 ngay lúc đó. Đặt header sau khi đã ghi body thì không có tác dụng (header đã được gửi đi rồi). Đây là lỗi hay gặp: "sao tôi set 404 mà client vẫn nhận 200?".

Sau khi gọi http.Error hoặc WriteJSON để báo lỗi, phải return ngay. Quên return thì code phía dưới vẫn chạy và ghi thêm vào response.

#http.Server với timeout: bắt buộc ở production

http.ListenAndServe(":8080", mux) dùng một server không có timeout nào. Kẻ tấn công có thể mở hàng nghìn kết nối rồi gửi header thật chậm, mỗi giây một byte (kiểu tấn công Slowloris), giữ hết tài nguyên của bạn.

Go · trích đoạnĐúng / nên làm
srv := &http.Server{
    Addr:              ":8080",
    Handler:           mux,
    ReadHeaderTimeout: 5 * time.Second,  // thời gian tối đa đọc header
    ReadTimeout:       15 * time.Second, // đọc cả request (header + body)
    WriteTimeout:      30 * time.Second, // từ lúc đọc xong request tới lúc ghi xong response
    IdleTimeout:       60 * time.Second, // giữ kết nối keep-alive rảnh bao lâu
    MaxHeaderBytes:    1 << 20,
}
log.Fatal(srv.ListenAndServe())

go vet không cảnh báo chỗ này, nhưng công cụ quét bảo mật gosec có (luật G112). Bài 13 bổ sung phần tắt server an toàn.

#Gọi API khác: http.Client cũng cần timeout

Go · trích đoạnSai / nguy hiểm
resp, err := http.Get("https://api.ben-thu-ba.vn/rates") // DefaultClient: KHÔNG có timeout

Nếu dịch vụ bên kia treo, goroutine của bạn chờ mãi, và mỗi request mới lại thêm một goroutine chờ. Sau vài phút server hết tài nguyên.

Go · trích đoạnĐúng / nên làm
var client = &http.Client{Timeout: 10 * time.Second} // tạo MỘT lần, dùng lại (có pool kết nối bên trong)

func fetchRates(ctx context.Context) (Rates, error) {
    req, err := http.NewRequestWithContext(ctx, http.MethodGet, "https://api.ben-thu-ba.vn/rates", nil)
    if err != nil {
        return Rates{}, err
    }
    resp, err := client.Do(req)
    if err != nil {
        return Rates{}, fmt.Errorf("gọi dịch vụ tỷ giá: %w", err)
    }
    defer resp.Body.Close() // luôn đóng, nếu không kết nối bị rò

    if resp.StatusCode != http.StatusOK {
        return Rates{}, fmt.Errorf("dịch vụ tỷ giá trả %d", resp.StatusCode)
    }
    var out Rates
    err = json.NewDecoder(io.LimitReader(resp.Body, 1<<20)).Decode(&out) // giới hạn cả dữ liệu đọc về
    return out, err
}

fetch của trình duyệt cũng không có timeout mặc định, nhưng ở frontend hậu quả là một spinner quay mãi cho một người. Ở backend, hậu quả là cả server chết dần cho tất cả mọi người.

#Ghép lại: API ghi chú trong bộ nhớ

main.go
package main

import (
    "encoding/json"
    "log"
    "net/http"
    "strconv"
    "strings"
    "sync"
    "time"
)

type Note struct {
    ID        int64     `json:"id"`
    Text      string    `json:"text"`
    CreatedAt time.Time `json:"createdAt"`
}

type store struct {
    mu     sync.Mutex // mỗi request một goroutine → dữ liệu dùng chung phải khoá
    nextID int64
    notes  map[int64]Note
}

func (s *store) list(w http.ResponseWriter, r *http.Request) {
    s.mu.Lock()
    out := make([]Note, 0, len(s.notes))
    for _, n := range s.notes {
        out = append(out, n)
    }
    s.mu.Unlock()
    writeJSON(w, http.StatusOK, out)
}

func (s *store) create(w http.ResponseWriter, r *http.Request) {
    var req struct {
        Text string `json:"text"`
    }
    r.Body = http.MaxBytesReader(w, r.Body, 1<<16)
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "JSON không hợp lệ"})
        return
    }
    req.Text = strings.TrimSpace(req.Text)
    if req.Text == "" || len([]rune(req.Text)) > 500 {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "Nội dung từ 1 đến 500 ký tự"})
        return
    }
    s.mu.Lock()
    s.nextID++
    n := Note{ID: s.nextID, Text: req.Text, CreatedAt: time.Now()}
    s.notes[n.ID] = n
    s.mu.Unlock()
    writeJSON(w, http.StatusCreated, n)
}

func (s *store) get(w http.ResponseWriter, r *http.Request) {
    id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
    if err != nil {
        writeJSON(w, http.StatusBadRequest, map[string]string{"error": "id không hợp lệ"})
        return
    }
    s.mu.Lock()
    n, ok := s.notes[id]
    s.mu.Unlock()
    if !ok {
        writeJSON(w, http.StatusNotFound, map[string]string{"error": "Không tìm thấy"})
        return
    }
    writeJSON(w, http.StatusOK, n)
}

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}

func main() {
    s := &store{notes: map[int64]Note{}}
    mux := http.NewServeMux()
    mux.HandleFunc("GET /notes", s.list)
    mux.HandleFunc("POST /notes", s.create)
    mux.HandleFunc("GET /notes/{id}", s.get)

    srv := &http.Server{Addr: ":8080", Handler: mux, ReadHeaderTimeout: 5 * time.Second}
    log.Println("http://localhost:8080")
    log.Fatal(srv.ListenAndServe())
}

Chạy go run . ở terminal 1, rồi thử ở terminal 2. -X POST chọn method, -H thêm header, -d là body gửi lên. -i in cả status và header của response:

Terminal — kết quả khi chạy

{"id":1,"text":"Học Go","createdAt":"2026-11-03T09:00:01.123456+07:00"}
$ curl -X POST localhost:8080/notes -H 'Content-Type: application/json' -d '{"text":"   "}'
{"error":"Nội dung từ 1 đến 500 ký tự"}
$ curl localhost:8080/notes

$ curl localhost:8080/notes/1

Tắt server rồi chạy lại: danh sách ghi chú trống trơn, vì dữ liệu chỉ nằm trong bộ nhớ (map). Bài 14, 15 sẽ lưu vào database.

Đọc chương trình theo thứ tự chạy:

  1. main tạo store rỗng, đăng ký 3 đường dẫn, mở server.
  2. Request POST /notes tới: Go gọi s.create. Hàm đọc JSON vào struct req, kiểm tra nội dung, khoá mutex, thêm ghi chú vào map, mở khoá, trả JSON với status 201.
  3. Request GET /notes/1 tới: Go gọi s.get. r.PathValue("id") lấy phần {id} trên đường dẫn (chuỗi "1"), đổi sang số, tìm trong map.
  4. Mutex cần thiết vì mỗi request chạy trên một goroutine riêng (bài 09): hai người cùng tạo ghi chú một lúc sẽ cùng ghi vào map.

Để ý: method s.list được truyền thẳng làm handler (method value, không có ngoặc). Đây là cách gọn để các handler dùng chung dữ liệu với nhau mà không cần biến toàn cục.

Câu hỏi nhanh. Handler gọi w.Write([]byte("lỗi")) rồi mới gọi w.WriteHeader(500). Client nhận status gì?

Lần Write đầu tiên tự gửi header với status 200. Gọi WriteHeader sau đó không còn tác dụng.

#Bài tập

Hoàn thiện API ghi chú

Thêm vào API ghi chú ở trên:

  • DELETE /notes/{id}: xoá, trả 204 No Content (không có body). Không có id đó thì 404.
  • PATCH /notes/{id}: sửa nội dung, body {"text":"..."}, kiểm tra như lúc tạo.
  • GET /notes?q=go: chỉ trả ghi chú có chứa từ khoá, không phân biệt hoa thường.
  • Danh sách luôn sắp xếp theo id tăng dần (map duyệt ngẫu nhiên, nên tạo vài ghi chú rồi gọi danh sách nhiều lần sẽ thấy thứ tự nhảy lung tung).

Gợi ý từng bước

  1. Đăng ký thêm đường dẫn trong main: mux.HandleFunc("DELETE /notes/{id}", s.remove), tương tự cho PATCH.
  2. Đoạn "đọc id từ đường dẫn" và "trả lỗi JSON" bị lặp ở nhiều handler. Tách thành hàm parseID(r) và writeErr(w, status, msg).
  3. remove: khoá, kiểm tra có không (_, ok := s.notes[id]), delete, mở khoá. Trả w.WriteHeader(http.StatusNoContent), không ghi body.
  4. update: giống create phần đọc và kiểm tra JSON, giống get phần tìm theo id. Struct trong map là bản sao: lấy ra, sửa, gán lại s.notes[id] = n.
  5. list: q := strings.ToLower(r.URL.Query().Get("q")). Khi duyệt map, chỉ thêm ghi chú nếu q == "" hoặc strings.Contains(strings.ToLower(n.Text), q). Cuối cùng slices.SortFunc(out, func(a, b Note) int { return cmp.Compare(a.ID, b.ID) }).
Xem lời giải

Toàn bộ main.go, thay hẳn file cũ:

main.go
package main

import (
    "cmp"
    "encoding/json"
    "errors"
    "log"
    "net/http"
    "slices"
    "strconv"
    "strings"
    "sync"
    "time"
)

type Note struct {
    ID        int64     `json:"id"`
    Text      string    `json:"text"`
    CreatedAt time.Time `json:"createdAt"`
}

type store struct {
    mu     sync.Mutex
    nextID int64
    notes  map[int64]Note
}

// ---- hàm dùng chung ----

func writeJSON(w http.ResponseWriter, status int, v any) {
    w.Header().Set("Content-Type", "application/json; charset=utf-8")
    w.WriteHeader(status)
    json.NewEncoder(w).Encode(v)
}

func writeErr(w http.ResponseWriter, status int, msg string) {
    writeJSON(w, status, map[string]string{"error": msg})
}

func parseID(r *http.Request) (int64, bool) {
    id, err := strconv.ParseInt(r.PathValue("id"), 10, 64)
    return id, err == nil && id > 0
}

// readText đọc {"text": "..."} và kiểm tra độ dài
func readText(w http.ResponseWriter, r *http.Request) (string, error) {
    var req struct {
        Text string `json:"text"`
    }
    r.Body = http.MaxBytesReader(w, r.Body, 1<<16)
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        return "", errors.New("JSON không hợp lệ")
    }
    text := strings.TrimSpace(req.Text)
    if text == "" || len([]rune(text)) > 500 {
        return "", errors.New("Nội dung từ 1 đến 500 ký tự")
    }
    return text, nil
}

// ---- handler ----

func (s *store) list(w http.ResponseWriter, r *http.Request) {
    q := strings.ToLower(r.URL.Query().Get("q"))
    s.mu.Lock()
    out := make([]Note, 0, len(s.notes))
    for _, n := range s.notes {
        if q == "" || strings.Contains(strings.ToLower(n.Text), q) {
            out = append(out, n)
        }
    }
    s.mu.Unlock()
    slices.SortFunc(out, func(a, b Note) int { return cmp.Compare(a.ID, b.ID) }) // id tăng dần
    writeJSON(w, http.StatusOK, out)
}

func (s *store) create(w http.ResponseWriter, r *http.Request) {
    text, err := readText(w, r)
    if err != nil {
        writeErr(w, http.StatusBadRequest, err.Error())
        return
    }
    s.mu.Lock()
    s.nextID++
    n := Note{ID: s.nextID, Text: text, CreatedAt: time.Now()}
    s.notes[n.ID] = n
    s.mu.Unlock()
    writeJSON(w, http.StatusCreated, n)
}

func (s *store) get(w http.ResponseWriter, r *http.Request) {
    id, ok := parseID(r)
    if !ok {
        writeErr(w, http.StatusBadRequest, "id không hợp lệ")
        return
    }
    s.mu.Lock()
    n, found := s.notes[id]
    s.mu.Unlock()
    if !found {
        writeErr(w, http.StatusNotFound, "Không tìm thấy")
        return
    }
    writeJSON(w, http.StatusOK, n)
}

func (s *store) update(w http.ResponseWriter, r *http.Request) {
    id, ok := parseID(r)
    if !ok {
        writeErr(w, http.StatusBadRequest, "id không hợp lệ")
        return
    }
    text, err := readText(w, r)
    if err != nil {
        writeErr(w, http.StatusBadRequest, err.Error())
        return
    }
    s.mu.Lock()
    n, found := s.notes[id]
    if found {
        n.Text = text   // n là bản sao lấy từ map...
        s.notes[id] = n // ...nên phải gán lại vào map
    }
    s.mu.Unlock()
    if !found {
        writeErr(w, http.StatusNotFound, "Không tìm thấy")
        return
    }
    writeJSON(w, http.StatusOK, n)
}

func (s *store) remove(w http.ResponseWriter, r *http.Request) {
    id, ok := parseID(r)
    if !ok {
        writeErr(w, http.StatusBadRequest, "id không hợp lệ")
        return
    }
    s.mu.Lock()
    _, found := s.notes[id]
    delete(s.notes, id)
    s.mu.Unlock()
    if !found {
        writeErr(w, http.StatusNotFound, "Không tìm thấy")
        return
    }
    w.WriteHeader(http.StatusNoContent) // 204: thành công, không có body
}

func (s *store) routes() *http.ServeMux {
    mux := http.NewServeMux()
    mux.HandleFunc("GET /notes", s.list)
    mux.HandleFunc("POST /notes", s.create)
    mux.HandleFunc("GET /notes/{id}", s.get)
    mux.HandleFunc("PATCH /notes/{id}", s.update)
    mux.HandleFunc("DELETE /notes/{id}", s.remove)
    return mux
}

func main() {
    s := &store{notes: map[int64]Note{}}
    srv := &http.Server{Addr: ":8080", Handler: s.routes(), ReadHeaderTimeout: 5 * time.Second}
    log.Println("http://localhost:8080")
    log.Fatal(srv.ListenAndServe())
}

Viết test cho handler

Dùng httptest (bài 10) viết test cho API ở bài tập trên, không cần bật server:

  • tạo ghi chú rỗng bị 400.
  • tạo đúng được 201, rồi lấy lại được bằng id.
  • lấy id không tồn tại bị 404.

Chạy với go test -race -v .

Gợi ý từng bước

  1. Tạo main_test.go cạnh main.go, cùng package main nên dùng được store và routes().
  2. Gửi request qua mux.ServeHTTP(rec, req) (không gọi thẳng handler), để r.PathValue("id") có giá trị: chính mux mới tách {id} ra.
  3. httptest.NewRequest("POST", "/notes", strings.NewReader(`{"text":"a"}`)) tạo request, httptest.NewRecorder() ghi lại response. Đọc rec.Code (status) và rec.Body.String().
  4. Viết một hàm nhỏ do(method, path, body) để không lặp ba dòng trên.
Xem lời giải
main_test.go
package main

import (
    "encoding/json"
    "net/http"
    "net/http/httptest"
    "strings"
    "testing"
)

// do gửi một request giả vào mux và trả về bản ghi response
func do(t *testing.T, h http.Handler, method, path, body string) *httptest.ResponseRecorder {
    t.Helper()
    req := httptest.NewRequest(method, path, strings.NewReader(body))
    req.Header.Set("Content-Type", "application/json")
    rec := httptest.NewRecorder()
    h.ServeHTTP(rec, req)
    return rec
}

func TestNotes(t *testing.T) {
    s := &store{notes: map[int64]Note{}} // mỗi test một store mới, sạch
    h := s.routes()

    t.Run("tạo rỗng bị 400", func(t *testing.T) {
        rec := do(t, h, "POST", "/notes", `{"text":"   "}`)
        if rec.Code != http.StatusBadRequest {
            t.Fatalf("status = %d, muốn 400", rec.Code)
        }
    })

    t.Run("tạo rồi lấy lại", func(t *testing.T) {
        rec := do(t, h, "POST", "/notes", `{"text":"Học Go"}`)
        if rec.Code != http.StatusCreated {
            t.Fatalf("tạo: status = %d, body = %s", rec.Code, rec.Body)
        }
        var created Note
        json.Unmarshal(rec.Body.Bytes(), &created) // đọc id vừa tạo từ response

        rec = do(t, h, "GET", "/notes/1", "")
        if rec.Code != http.StatusOK {
            t.Fatalf("lấy: status = %d", rec.Code)
        }
        var got Note
        json.Unmarshal(rec.Body.Bytes(), &got)
        if got.ID != created.ID || got.Text != "Học Go" {
            t.Errorf("lấy được %+v, muốn %+v", got, created)
        }
    })

    t.Run("id không tồn tại bị 404", func(t *testing.T) {
        rec := do(t, h, "GET", "/notes/999", "")
        if rec.Code != http.StatusNotFound {
            t.Errorf("status = %d, muốn 404", rec.Code)
        }
    })
}

Giải thích: h.ServeHTTP(rec, req) chạy đúng con đường một request thật đi qua (mux tìm handler, handler ghi response), chỉ khác là không có mạng.
