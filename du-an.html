Dự án: API "Sổ bài tập" chuẩn production

Tự xây API cho giáo viên và phụ huynh: đăng nhập, lớp, bài tập, nộp bài, phân quyền, phân trang, việc chạy nền, Docker, test.

Học xong bài này bạn sẽ:
  • Ghép mọi kiến thức thành một dịch vụ hoàn chỉnh
  • Có một dự án để đưa vào CV
  • Tự tin nhận task backend Go

#Đề bài

Xây API cho ứng dụng "Sổ bài tập": giáo viên giao bài về nhà cho lớp, học sinh nộp bài, giáo viên chấm. Đây là một sản phẩm có thật trên thị trường, đủ các bài toán bạn đã học: phân quyền theo sở hữu, giới hạn, tranh chấp, việc chạy nền, upload file.

Vai tròLàm được gì
Giáo viênTạo lớp (miễn phí tối đa 2 lớp), xem mã lớp, xem danh sách học sinh, giao bài, xem ai đã nộp / chưa nộp, chấm điểm và nhận xét
Học sinhVào lớp bằng mã lớp (không vượt sĩ số), xem bài tập của các lớp mình học, nộp bài (văn bản), xem điểm của chính mình, nộp lại khi chưa được chấm

Yêu cầu phi chức năng: chỉ dùng Go + PostgreSQL (+ Redis tuỳ chọn), có test, chạy được bằng một lệnh docker compose up, đạt checklist bảo mật ở bài 19.

CREATE TABLE users (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email         text NOT NULL UNIQUE CHECK (email = lower(email)),
    name          text NOT NULL CHECK (char_length(name) BETWEEN 1 AND 80),
    role          text NOT NULL CHECK (role IN ('teacher', 'student')),
    password_hash text NOT NULL,
    created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE sessions (
    token_hash  bytea PRIMARY KEY,
    user_id     bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    expires_at  timestamptz NOT NULL
);
CREATE INDEX ON sessions (user_id);

CREATE TABLE classes (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    teacher_id  bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name        text NOT NULL CHECK (char_length(name) BETWEEN 1 AND 60),
    join_code   text NOT NULL UNIQUE,
    capacity    int  NOT NULL CHECK (capacity BETWEEN 1 AND 80),
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON classes (teacher_id);

CREATE TABLE enrollments (
    class_id    bigint NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    student_id  bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    joined_at   timestamptz NOT NULL DEFAULT now(),
    PRIMARY KEY (class_id, student_id)
);
CREATE INDEX ON enrollments (student_id);

CREATE TABLE assignments (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    class_id    bigint NOT NULL REFERENCES classes(id) ON DELETE CASCADE,
    title       text NOT NULL CHECK (char_length(title) BETWEEN 1 AND 200),
    due_date    date NOT NULL,
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX ON assignments (class_id, due_date DESC, id DESC);

CREATE TABLE submissions (
    assignment_id bigint NOT NULL REFERENCES assignments(id) ON DELETE CASCADE,
    student_id    bigint NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    content       text NOT NULL CHECK (char_length(content) BETWEEN 1 AND 5000),
    score         numeric(4,2) CHECK (score BETWEEN 0 AND 10),
    comment       text CHECK (char_length(comment) <= 500),
    submitted_at  timestamptz NOT NULL DEFAULT now(),
    graded_at     timestamptz,
    PRIMARY KEY (assignment_id, student_id)
);
CREATE INDEX ON submissions (student_id);

CREATE TABLE jobs (
    id         bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    kind       text NOT NULL,
    payload    jsonb NOT NULL,
    run_at     timestamptz NOT NULL DEFAULT now(),
    attempts   int NOT NULL DEFAULT 0,
    last_error text,
    status     text NOT NULL DEFAULT 'pending'
);
CREATE INDEX jobs_ready ON jobs (run_at) WHERE status = 'pending';

#Lộ trình làm từng bước

Làm theo thứ tự. Mỗi bước có tiêu chí "xong" rõ ràng, commit sau mỗi bước. Phần lớn code bạn đã có sẵn trong lời giải bài tập của các bài trước, mục "Bắt đầu từ" ở mỗi bước chỉ chỗ để chép sang rồi sửa.

Bước 1: khung dự án (bài 08, 11, 13)

  • go mod init, cấu trúc thư mục, config.Load(), logger slog JSON.
  • http.Server có timeout, graceful shutdown, middleware RequestID / Logger / Recover / SecurityHeaders.
  • GET /livez, GET /readyz.
  • Bắt đầu từ: lời giải bài tập bài 13 (dự án notes-api): đã có đủ cấu trúc thư mục, ba middleware, run() với graceful shutdown. Đổi tên module, bỏ phần ghi chú.
  • Xong khi: go run ./cmd/api chạy, Ctrl+C tắt sạch, mỗi request có một dòng log JSON.

Bước 2: database (bài 14, 15)

  • Compose với Postgres, migration bằng goose, pool pgx, /readyz ping database.
  • Helper test: tạo database / schema riêng cho mỗi test.
  • Bắt đầu từ: lược đồ bài 14 làm file migration đầu tiên (thêm dòng -- +goose Up / -- +goose Down như ví dụ bài 15), compose.yaml ở lời giải bài 22.
  • Xong khi: goose up rồi goose down rồi goose up chạy sạch.

Bước 3: đăng ký, đăng nhập (bài 18)

internal/service/auth.go (trích) · trích đoạn
func (s *Auth) Login(ctx context.Context, email, password string) (token string, err error) {
    email = strings.ToLower(strings.TrimSpace(email))
    ok, err := s.limiter.Allow(ctx, "login:"+email) // 5 lần / 15 phút
    if err != nil {
        return "", err
    }
    if !ok {
        return "", domain.ErrTooManyRequests
    }
    u, err := s.store.UserByEmail(ctx, email)
    if errors.Is(err, domain.ErrNotFound) {
        // Vẫn tốn thời gian như khi có tài khoản, để không lộ email nào đã đăng ký qua thời gian phản hồi
        bcrypt.CompareHashAndPassword(s.dummyHash, []byte(password))
        return "", domain.ErrBadCredentials
    }
    if err != nil {
        return "", err
    }
    if bcrypt.CompareHashAndPassword([]byte(u.PasswordHash), []byte(password)) != nil {
        return "", domain.ErrBadCredentials
    }
    token, hash, err := NewSessionToken()
    if err != nil {
        return "", err
    }
    return token, s.store.CreateSession(ctx, hash, u.ID, time.Now().Add(30*24*time.Hour))
}
  • Bắt đầu từ: auth.go trong lời giải bài 18. Đoạn trích ở trên là cùng logic đó, chỉ tách sang tầng service (bài 13) và thêm một chi tiết: so mật khẩu với một chuỗi băm giả khi không có email, để thời gian trả lời như nhau.
  • Xong khi: có test cho: đăng ký trùng email (kể cả khác hoa thường), đăng nhập sai không lộ email tồn tại, quá 5 lần bị 429, đăng xuất thì cookie cũ bị 401.

Bước 4: lớp học và hạn mức (bài 16)

Vào lớp: kiểm sĩ số NGAY trong câu ghi
INSERT INTO enrollments (class_id, student_id)
SELECT c.id, $2
FROM classes c
WHERE c.join_code = $1
  AND (SELECT count(*) FROM enrollments e WHERE e.class_id = c.id) < c.capacity
ON CONFLICT DO NOTHING
RETURNING class_id;

Câu trên vẫn có khe hở ở mức cô lập Read Committed: hai học sinh vào lớp còn đúng 1 chỗ có thể cùng đếm thấy chỗ trống. Hãy khoá dòng lớp trước trong transaction (SELECT ... FROM classes WHERE join_code = $1 FOR UPDATE), giống cách khoá dòng giáo viên ở bài 16. Viết test 20 goroutine cùng vào lớp sĩ số 5 để chứng minh.

  • Mã lớp: 8 ký tự ngẫu nhiên từ crypto/rand, bỏ các ký tự dễ nhầm (0/O, 1/I/L), UNIQUE, trùng thì sinh lại.
  • Bắt đầu từ: CreateClassWithQuota và test 10 goroutine trong lời giải bài 16. Vào lớp làm y hệt, chỉ đổi dòng bị khoá từ giáo viên sang lớp.
  • Xong khi: test đồng thời chứng minh không vượt hạn mức 2 lớp và không vượt sĩ số.

Bước 5: bài tập, nộp bài, chấm bài (bài 12, 15, 19)

Nộp bài: học sinh phải thuộc lớp, bài chưa được chấm
INSERT INTO submissions (assignment_id, student_id, content)
SELECT a.id, $2, $3
FROM assignments a
JOIN enrollments e ON e.class_id = a.class_id AND e.student_id = $2
WHERE a.id = $1
ON CONFLICT (assignment_id, student_id)
DO UPDATE SET content = EXCLUDED.content, submitted_at = now()
WHERE submissions.score IS NULL
RETURNING submitted_at;
-- 0 dòng: hoặc không thuộc lớp / không có bài (404), hoặc đã chấm (409).
-- Phân biệt bằng một truy vấn kiểm tra sau khi thất bại.
Danh sách nộp bài cho giáo viên: kiểm quyền + LEFT JOIN
SELECT u.id, u.name, s.content, s.score, s.submitted_at
FROM assignments a
JOIN classes c      ON c.id = a.class_id AND c.teacher_id = $1
JOIN enrollments en ON en.class_id = a.class_id
JOIN users u        ON u.id = en.student_id
LEFT JOIN submissions s ON s.assignment_id = a.id AND s.student_id = en.student_id
WHERE a.id = $2
ORDER BY u.name, u.id
LIMIT $3 OFFSET $4;
  • Bắt đầu từ: AssignmentStore trong lời giải bài 15 (đã kiểm quyền giáo viên trong mọi câu SQL), cách đọc lỗi 23505 ở bài 15, Validate() ở bài 12.
  • Xong khi: có bộ test phân quyền: giáo viên B không xem / chấm được bài của lớp giáo viên A, học sinh không thuộc lớp không nộp được, học sinh không xem được bài nộp của bạn khác, học sinh không gọi được endpoint chấm bài.

Bước 6: việc chạy nền (bài 20)

  • Giao bài → trong cùng transaction chèn job assignment.created.
  • cmd/worker: lấy việc bằng SKIP LOCKED, "gửi thông báo" (ghi log), bảng notifications_sent chống gửi trùng, thử lại có backoff, dừng an toàn.
  • Việc định kỳ: 19 giờ mỗi ngày (giờ Việt Nam) nhắc học sinh có bài hạn ngày mai chưa nộp. Chạy 2 worker cùng lúc mà mỗi học sinh vẫn chỉ nhận một lời nhắc mỗi ngày.
  • Bắt đầu từ: lời giải bài 20: bảng jobs, notifications_sent, vòng lặp worker, assign tạo bài và việc trong một transaction. Việc định kỳ: thêm bảng reminders_sent(student_id, day) có khoá chính kép, chèn được mới gửi.

Bước 7: quan sát và đóng gói (bài 21, 22)

  • Metrics RED ở cổng nội bộ, pprof ở localhost.
  • Dockerfile nhiều giai đoạn, Compose chạy cả api + worker + postgres, GitHub Actions: vet, test -race, govulncheck, build.
  • Bắt đầu từ: middleware metrics trong lời giải bài 21, Dockerfile, compose.yaml, .github/workflows/ci.yml trong lời giải bài 22. Thêm một service worker vào compose, build cùng image nhưng chạy lệnh khác.
  • Xong khi: clone repo về máy sạch, docker compose up là chạy, CI xanh.

Bước 8 (nâng cao, chọn làm)

  • Upload ảnh bài làm: presigned URL tới S3 / R2 / MinIO, giới hạn dung lượng và số file, kiểm quyền khi tải về.
  • Cache tổng quan lớp bằng Redis + singleflight, xoá cache khi có bài nộp mới.
  • Cursor pagination cho danh sách thông báo.
  • OpenAPI cho toàn bộ API, sinh client TypeScript và làm một giao diện nhỏ bằng framework frontend bạn quen.
  • Deploy lên Cloud Run hoặc Fly.io với Postgres có quản lý.

#Đưa vào CV

Khi xong, repo của bạn nên có một README trả lời được: hệ thống làm gì, chạy thế nào bằng một lệnh, kiến trúc (một sơ đồ), các quyết định thiết kế và vì sao (vì sao session thay vì JWT, vì sao hàng đợi trong Postgres, cách chống vượt sĩ số), và cách chạy test. Người phỏng vấn backend hỏi đúng những câu đó.

Phỏng vấn backend Go thường hỏi: goroutine khác thread thế nào, channel có đệm và không đệm, cách tránh data race, context dùng để làm gì, index hoạt động ra sao, transaction và mức cô lập, xử lý hai request đồng thời, thiết kế một hệ thống nhỏ (rút gọn link, hệ thống thông báo). Bạn đã làm tất cả những thứ đó trong dự án này.

#Bạn đã đi được tới đây

Nếu đã làm xong 8 bước, bạn có đủ nền tảng để nhận task backend Go ở công ty: đọc hiểu code hiện có, viết endpoint mới đúng chuẩn, thiết kế bảng, viết test, và biết những chỗ nguy hiểm cần hỏi người có kinh nghiệm hơn. Phần còn lại học qua công việc thật: mỗi sự cố, mỗi lần review code là một bài học mới.

Giữ hai trang tra cứu bên cạnh khi làm việc: Từ điển thuật ngữ và Nguyên tắc làm backend.
