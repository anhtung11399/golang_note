Hàm, rẽ nhánh, vòng lặp và defer

if / for / switch kiểu Go, hàm trả nhiều giá trị, closure, defer và thứ tự chạy của nó.

Học xong bài này bạn sẽ:
  • Viết hàm trả về (giá trị, lỗi)
  • Dùng for cho mọi kiểu vòng lặp
  • Dùng defer để dọn tài nguyên

#if: không cần ngoặc tròn, bắt buộc ngoặc nhọn

Go
if score >= 8 {
    fmt.Println("Giỏi")
} else if score >= 6.5 {
    fmt.Println("Khá")
} else {
    fmt.Println("Cần cố gắng")
}

Điểm đặc biệt: if có thể kèm một câu lệnh khởi tạo trước dấu ;. Biến tạo ra chỉ sống trong khối if/else đó. Mẫu này xuất hiện ở mọi code Go:

Go
if n, err := strconv.Atoi(input); err != nil {
    fmt.Println("không phải số:", err)
} else {
    fmt.Println("số là", n)
}
// n và err không còn tồn tại ở đây

#for: vòng lặp duy nhất

Go không có while, do, forEach. Chỉ có for, với nhiều dạng:

Go
// 1. Kiểu C
for i := 0; i < 3; i++ { }

// 2. Kiểu while
for balance > 0 { balance -= 10 }

// 3. Vô hạn (thoát bằng break hoặc return)
for {
    if done() {
        break
    }
}

// 4. range trên slice: chỉ số và giá trị
names := []string{"An", "Bình", "Chi"}
for i, name := range names {
    fmt.Println(i, name)
}
for _, name := range names { }   // bỏ chỉ số bằng _

// 5. range trên map: thứ tự NGẪU NHIÊN (bài 04)
for key, value := range ages { }

// 6. range trên số nguyên (Go 1.22+): 0, 1, 2
for i := range 3 { }
JavaScriptGo
arr.forEach((x, i) => ...)for i, x := range arr { ... }
for (const x of arr)for _, x := range arr
while (cond)for cond
arr.map(f), arr.filter(f)Viết vòng for (Go ưa code rõ ràng hơn chuỗi hàm). Từ Go 1.21 có package slices với slices.Contains, slices.Index, slices.Sort...

Biến trong for _, x := range là bản sao của phần tử. Sửa x.Score = 10 không làm thay đổi phần tử trong slice. Muốn sửa, dùng chỉ số: items[i].Score = 10.

#switch: không cần break

Go
switch method {
case "GET", "HEAD":
    fmt.Println("đọc")
case "POST":
    fmt.Println("tạo")
default:
    fmt.Println("khác")
}

Mỗi case tự dừng sau khi chạy xong (ngược với JavaScript, nơi quên break là lỗi). Muốn chạy tiếp case dưới thì phải viết rõ fallthrough, rất hiếm khi dùng.

switch không có biểu thức là cách viết gọn cho chuỗi if/else:

Go
switch {
case score >= 8:
    grade = "Giỏi"
case score >= 6.5:
    grade = "Khá"
default:
    grade = "Trung bình"
}

Trả về nhiều giá trị

Đây là tính năng làm nên phong cách Go. Hàm có thể lỗi thì trả về (kết quả, error), và người gọi phải nhận cả hai.

Go
func divide(a, b float64) (float64, error) {
    if b == 0 {
        return 0, errors.New("không chia được cho 0")
    }
    return a / b, nil
}

result, err := divide(10, 0)
if err != nil {
    fmt.Println("lỗi:", err)
    return
}
fmt.Println(result)

Thay cho try { ... } catch (e) { ... }, lỗi trong Go là một giá trị trả về bình thường. Không có lỗi nào "bay" lên qua nhiều tầng mà bạn không thấy. Bài 07 nói kỹ về cách này.

Guard clause: thoát sớm, giữ luồng chính sát lề trái

Phong cách Go: xử lý trường hợp lỗi trước rồi return, đoạn code "đường thẳng" nằm sát lề trái. Tránh lồng if nhiều tầng.

GoSai / nguy hiểm
func process(u *User) error {
    if u != nil {
        if u.Active {
            if u.Email != "" {
                return send(u.Email)
            } else {
                return errors.New("thiếu email")
            }
        }
    }
    return nil
}
GoĐúng / nên làm
func process(u *User) error {
    if u == nil || !u.Active {
        return nil
    }
    if u.Email == "" {
        return errors.New("thiếu email")
    }
    return send(u.Email)
}

Hàm có số tham số thay đổi (variadic)

Go
func sum(nums ...int) int {   // nums là []int
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

sum(1, 2, 3)
list := []int{4, 5}
sum(list...)                  // trải slice ra, giống ...spread trong JS

#Hàm là giá trị, closure

Giống JavaScript, hàm có thể gán vào biến, truyền làm tham số, trả về từ hàm khác, và "nhớ" biến bên ngoài (closure).

Go
func counter() func() int {
    n := 0
    return func() int {
        n++
        return n
    }
}

next := counter()
next() // 1
next() // 2

// Hàm làm tham số: rất hay gặp ở middleware HTTP (bài 13)
func retry(times int, fn func() error) error {
    var err error
    for range times {
        if err = fn(); err == nil {
            return nil
        }
    }
    return err
}

Từ Go 1.22, mỗi vòng lặp for tạo biến lặp mới cho mỗi lần lặp. Lỗi kinh điển "mọi goroutine / closure đều thấy giá trị cuối cùng của i" (giống lỗi var trong vòng for của JavaScript thời trước let) đã hết. Bạn vẫn sẽ thấy dòng i := i trong code cũ: đó là cách sửa lỗi này trước Go 1.22.

#defer: dọn dẹp khi hàm kết thúc

defer hẹn một lời gọi hàm để chạy ngay trước khi hàm hiện tại trả về, kể cả khi trả về sớm hay khi panic. Dùng để đóng file, đóng kết nối, mở khoá, rollback giao dịch.

Go
func readConfig(path string) ([]byte, error) {
    f, err := os.Open(path)
    if err != nil {
        return nil, err
    }
    defer f.Close() // dù return ở đâu bên dưới, file vẫn được đóng

    return io.ReadAll(f)
}

Nhiều defer chạy theo thứ tự ngược lại (vào sau ra trước, như một chồng đĩa):

Go
func main() {
    defer fmt.Println("1")
    defer fmt.Println("2")
    defer fmt.Println("3")
    fmt.Println("thân hàm")
}
// thân hàm
// 3
// 2
// 1

Tham số của lời gọi defer được tính ngay lúc gặp dòng defer, không phải lúc chạy:

Go
start := time.Now()
defer fmt.Println("mất", time.Since(start))          // sai: time.Since tính ngay, luôn ~0
defer func() { fmt.Println("mất", time.Since(start)) }() // đúng: bọc trong hàm

Và đừng defer trong vòng lặp dài (ví dụ mở 10.000 file): các defer chỉ chạy khi hàm kết thúc, nên file mở chồng chất. Hãy tách thân vòng lặp ra một hàm riêng.

Mẫu đo thời gian xử lý bằng defer có ở hầu hết middleware ghi log của các dịch vụ Go: ghi start ở đầu, defer một hàm ghi log thời gian khi request xong. Bạn sẽ tự viết nó ở bài 13.

Câu hỏi nhanh. Đoạn code sau in ra gì? x := 1; defer fmt.Println(x); x = 2

Tham số x được tính ngay lúc dòng defer chạy (lúc đó x = 1). Gán x = 2 sau đó không ảnh hưởng.

#Bài tập

FizzBuzz phiên bản Việt và đếm thời gian

In từ 1 đến 30: chia hết cho 3 in "Lẻ", chia hết cho 5 in "Chẵn", chia hết cho cả hai in "Tròn", còn lại in số. Dùng switch không biểu thức, và dùng defer để in tổng thời gian chạy khi hàm main kết thúc.

Xem lời giải
Go
package main

import (
    "fmt"
    "time"
)

func main() {
    start := time.Now()
    defer func() { fmt.Println("xong sau", time.Since(start)) }()

    for i := 1; i <= 30; i++ {
        switch {
        case i%15 == 0:
            fmt.Println("Tròn")
        case i%3 == 0:
            fmt.Println("Lẻ")
        case i%5 == 0:
            fmt.Println("Chẵn")
        default:
            fmt.Println(i)
        }
    }
}
Hàm thử lại có chờ tăng dần

Viết retry(attempts int, base time.Duration, fn func() error) error: gọi fn, lỗi thì chờ base, rồi base*2, base*4... cho tới khi hết lượt. Đây chính là exponential backoff, thứ bạn sẽ dùng khi gọi API bên thứ ba (bài 20).

Xem lời giải
Go
func retry(attempts int, base time.Duration, fn func() error) error {
    var err error
    wait := base
    for i := range attempts {
        if err = fn(); err == nil {
            return nil
        }
        if i < attempts-1 {
            time.Sleep(wait)
            wait *= 2
        }
    }
    return fmt.Errorf("hết %d lần thử: %w", attempts, err)
}

Ngoài thực tế người ta còn thêm jitter (cộng một khoảng ngẫu nhiên vào thời gian chờ) để hàng nghìn client không cùng thử lại vào đúng một thời điểm. Bài viết "Exponential Backoff And Jitter" trên blog kiến trúc của AWS giải thích rất rõ điều này.
