Hàm, rẽ nhánh, vòng lặp và defer

if / for / switch kiểu Go, hàm trả nhiều giá trị, closure, defer và thứ tự chạy của nó.

Học xong bài này bạn sẽ:
  • Viết hàm trả về (giá trị, lỗi)
  • Dùng for cho mọi kiểu vòng lặp
  • Dùng defer để dọn tài nguyên

#if: không cần ngoặc tròn, bắt buộc ngoặc nhọn

Go
package main

import "fmt"

func main() {
    score := 7.0

    if score >= 8 { // không có ( ) quanh điều kiện, nhưng BẮT BUỘC có { }
        fmt.Println("Giỏi")
    } else if score >= 6.5 {
        fmt.Println("Khá")
    } else {
        fmt.Println("Cần cố gắng")
    }
}
Terminal — kết quả khi chạy
Khá

Thử đổi score thành 9.0 hay 5.0 rồi chạy lại để thấy dòng in ra thay đổi. Điều kiện phải là bool thật: if score { } là lỗi biên dịch (Go không có "truthy / falsy" như JS).

if có câu lệnh khởi tạo

if có thể chạy một câu lệnh trước dấu ; rồi mới kiểm tra điều kiện. Biến tạo ra ở đó chỉ dùng được bên trong khối if/else. Mẫu này xuất hiện ở mọi code Go:

Go
package main

import (
    "fmt"
    "strconv"
)

func main() {
    input := "42"

    //  [câu lệnh chạy trước]            ; [điều kiện]
    if n, err := strconv.Atoi(input); err != nil {
        fmt.Println("không phải số:", err)
    } else {
        fmt.Println("số là", n)
    }
    // n và err không còn tồn tại ở đây: viết fmt.Println(n) sẽ lỗi "undefined: n"
}
Terminal — kết quả khi chạy
số là 42

Đọc thành lời: "đổi input sang số, được n và err. Nếu err khác nil (có lỗi) thì báo lỗi, ngược lại in số". Đổi input thành "abc" để thấy nhánh lỗi.

#for: vòng lặp duy nhất

Go không có while, do, forEach. Chỉ có từ khoá for, viết theo nhiều dạng. Chạy chương trình dưới để thấy từng dạng in ra gì:

Go
package main

import "fmt"

func main() {
    // 1. Kiểu C: khởi tạo; điều kiện; bước tăng (giống JS, chỉ bỏ ngoặc tròn)
    for i := 0; i < 3; i++ {
        fmt.Print(i, " ")
    }
    fmt.Println("<- dạng 1")

    // 2. Kiểu while: chỉ có điều kiện
    balance := 30
    for balance > 0 {
        balance -= 10
        fmt.Print(balance, " ")
    }
    fmt.Println("<- dạng 2")

    // 3. Vô hạn: không có gì sau for, thoát bằng break
    tries := 0
    for {
        tries++
        if tries == 3 {
            break
        }
    }
    fmt.Println("thử", tries, "lần <- dạng 3")

    // 4. range trên slice: mỗi vòng cho chỉ số i và phần tử name
    names := []string{"An", "Bình", "Chi"}
    for i, name := range names {
        fmt.Print(i, "=", name, " ")
    }
    fmt.Println("<- dạng 4")

    // Không cần chỉ số thì đặt _ (Go bắt buộc dùng mọi biến đã khai báo)
    for _, name := range names {
        fmt.Print(name, " ")
    }
    fmt.Println("<- dạng 4, bỏ chỉ số")

    // 5. range trên số nguyên (Go 1.22+): i = 0, 1, 2
    for i := range 3 {
        fmt.Print(i, " ")
    }
    fmt.Println("<- dạng 5")
}

Biến trong for _, x := range là bản sao của phần tử. Sửa x.Score = 10 không làm thay đổi phần tử trong slice. Muốn sửa, dùng chỉ số: items[i].Score = 10. Bài 05 có ví dụ chạy được cho chuyện này.

#switch: không cần break

Go
package main

import "fmt"

func main() {
    method := "HEAD"

    switch method {
    case "GET", "HEAD": // một case khớp nhiều giá trị, cách nhau bởi dấu phẩy
        fmt.Println("đọc")
    case "POST":
        fmt.Println("tạo")
    default: // không khớp case nào
        fmt.Println("khác")
    }
}
Terminal — kết quả khi chạy
đọc

Mỗi case tự dừng sau khi chạy xong (ngược với JavaScript, nơi quên break là lỗi). Muốn chạy tiếp case dưới thì phải viết rõ fallthrough, rất hiếm khi dùng.

switch không có giá trị phía sau là cách viết gọn cho chuỗi if / else if: Go thử từng case từ trên xuống, gặp điều kiện đúng đầu tiên thì chạy case đó.

Go
package main

import "fmt"

func main() {
    score := 7.0
    var grade string

    switch { // không có gì sau switch
    case score >= 8:
        grade = "Giỏi"
    case score >= 6.5: // 7.0 >= 6.5 đúng: chạy case này rồi dừng
        grade = "Khá"
    default:
        grade = "Trung bình"
    }
    fmt.Println(grade)
}

Trả về nhiều giá trị

Đây là tính năng làm nên phong cách Go. Hàm có thể lỗi thì trả về hai giá trị: kết quả và lỗi. Người gọi nhận cả hai, rồi kiểm tra lỗi trước khi dùng kết quả.

Go
package main

import (
    "errors"
    "fmt"
)

// (float64, error): hàm trả về 2 giá trị, đặt trong ngoặc
func divide(a, b float64) (float64, error) {
    if b == 0 {
        // có lỗi: kết quả để 0 (không ai dùng), kèm một lỗi
        return 0, errors.New("không chia được cho 0")
    }
    // thành công: kết quả thật, lỗi là nil (không có lỗi)
    return a / b, nil
}

func main() {
    result, err := divide(10, 4) // nhận 2 giá trị vào 2 biến
    if err != nil {
        fmt.Println("lỗi:", err)
    } else {
        fmt.Println("kết quả:", result)
    }

    result, err = divide(10, 0)
    if err != nil {
        fmt.Println("lỗi:", err)
    } else {
        fmt.Println("kết quả:", result)
    }
}
Terminal — kết quả khi chạy
kết quả: 2.5
lỗi: không chia được cho 0

Thay cho try { ... } catch (e) { ... }, lỗi trong Go là một giá trị trả về bình thường. Không có lỗi nào "bay" lên qua nhiều tầng mà bạn không thấy. Gần giống kiểu const [data, error] = await to(promise) mà một số dự án JS hay dùng. Bài 07 nói kỹ.

Guard clause: thoát sớm, giữ luồng chính sát lề trái

Phong cách Go: xử lý trường hợp lỗi trước rồi return luôn, phần code chính nằm sát lề trái. Tránh if lồng nhiều tầng. Hai hàm dưới làm cùng một việc, nhưng hàm thứ hai dễ đọc hơn hẳn:

Go · trích đoạnSai / nguy hiểm
func process(u *User) error {
    if u != nil {
        if u.Active {
            if u.Email != "" {
                return send(u.Email)
            } else {
                return errors.New("thiếu email")
            }
        }
    }
    return nil
}
Go · trích đoạnĐúng / nên làm
func process(u *User) error {
    if u == nil || !u.Active { // không có người dùng, hoặc đã khoá: bỏ qua
        return nil
    }
    if u.Email == "" { // thiếu dữ liệu: báo lỗi
        return errors.New("thiếu email")
    }
    return send(u.Email) // tới đây thì mọi thứ đã hợp lệ
}

*User là con trỏ tới một User (bài 05). || là "hoặc", ! là "không", giống JS.

Hàm có số tham số thay đổi (variadic)

Go
package main

import "fmt"

// ...int: nhận bao nhiêu số int cũng được. Bên trong hàm, nums là một slice []int
func sum(nums ...int) int {
    total := 0
    for _, n := range nums {
        total += n
    }
    return total
}

func main() {
    fmt.Println(sum())        // không truyền gì: nums rỗng
    fmt.Println(sum(1, 2, 3))

    list := []int{4, 5}
    fmt.Println(sum(list...)) // trải slice thành từng tham số, giống sum(...list) trong JS
}

#Hàm là giá trị, closure

Giống JavaScript, hàm có thể gán vào biến, truyền làm tham số, trả về từ hàm khác, và "nhớ" biến bên ngoài nó (closure).

Go
package main

import (
    "errors"
    "fmt"
)

// counter trả về một HÀM. Kiểu trả về "func() int" = hàm không tham số, trả về int
func counter() func() int {
    n := 0
    return func() int { // hàm bên trong "nhớ" biến n của counter
        n++
        return n
    }
}

// retry nhận một hàm fn làm tham số và gọi lại tối đa times lần
func retry(times int, fn func() error) error {
    var err error
    for i := range times {
        err = fn()
        if err == nil {
            return nil // thành công thì dừng
        }
        fmt.Println("lần", i+1, "lỗi:", err)
    }
    return err // hết lượt: trả lỗi cuối cùng
}

func main() {
    next := counter()
    fmt.Println(next(), next(), next()) // n tăng dần qua các lần gọi

    calls := 0
    err := retry(5, func() error { // truyền một hàm viết ngay tại chỗ, giống arrow function
        calls++
        if calls < 3 {
            return errors.New("mạng chập chờn")
        }
        return nil // lần thứ 3 thì thành công
    })
    fmt.Println("kết quả:", err, "sau", calls, "lần gọi")
}
Terminal — kết quả khi chạy
1 2 3
lần 1 lỗi: mạng chập chờn
lần 2 lỗi: mạng chập chờn
kết quả: <nil> sau 3 lần gọi

So với JS: func() error { ... } viết ngay trong lời gọi chính là () => { ... }. Hàm truyền vào thay đổi được biến calls bên ngoài, đó là closure. Kiểu hàm nhận hàm này rất hay gặp ở middleware HTTP (bài 13).

Từ Go 1.22, mỗi vòng lặp for tạo biến lặp mới cho mỗi lần lặp. Lỗi kinh điển "mọi goroutine / closure đều thấy giá trị cuối cùng của i" (giống lỗi var trong vòng for của JavaScript thời trước let) đã hết. Bạn vẫn sẽ thấy dòng i := i trong code cũ: đó là cách sửa lỗi này trước Go 1.22.

#defer: dọn dẹp khi hàm kết thúc

defer hẹn một lời gọi hàm để chạy ngay trước khi hàm hiện tại trả về, kể cả khi trả về sớm hay khi panic. Dùng để đóng file, đóng kết nối, mở khoá, rollback giao dịch. Gần giống khối finally trong JS, nhưng viết ngay cạnh chỗ mở tài nguyên.

Go
package main

import "fmt"

func main() {
    defer fmt.Println("1")
    defer fmt.Println("2")
    defer fmt.Println("3")
    fmt.Println("thân hàm")
} // tới đây main kết thúc, các defer mới chạy
Terminal — kết quả khi chạy

Nhiều defer chạy theo thứ tự ngược lại (vào sau ra trước, như một chồng đĩa):

Cách dùng thật: mở file xong là defer đóng ngay ở dòng kế tiếp, nên không bao giờ quên đóng dù hàm có return ở bao nhiêu chỗ:

Go
package main

import (
    "fmt"
    "io"
    "os"
)

func readConfig(path string) ([]byte, error) {
    f, err := os.Open(path) // mở file
    if err != nil {
        return nil, err // mở lỗi: chưa có gì để đóng
    }
    defer f.Close() // mở được rồi: hẹn đóng. Dù return ở đâu bên dưới, file vẫn được đóng

    return io.ReadAll(f) // đọc hết nội dung file
}

func main() {
    _, err := readConfig("khong-co-file-nay.json")
    fmt.Println(err)
}
Terminal — kết quả khi chạy
open khong-co-file-nay.json: no such file or directory

Tham số của lời gọi defer được tính ngay lúc gặp dòng defer, không phải lúc chạy:

Go · trích đoạn
start := time.Now()
defer fmt.Println("mất", time.Since(start))              // sai: time.Since tính ngay, luôn ~0
defer func() { fmt.Println("mất", time.Since(start)) }() // đúng: bọc trong hàm, tính lúc chạy

Và đừng defer trong vòng lặp dài (ví dụ mở 10.000 file): các defer chỉ chạy khi hàm kết thúc, nên file mở chồng chất. Hãy tách thân vòng lặp ra một hàm riêng.

Mẫu đo thời gian xử lý bằng defer có ở hầu hết middleware ghi log của các dịch vụ Go: ghi start ở đầu, defer một hàm ghi log thời gian khi request xong. Bạn sẽ tự viết nó ở bài 13.

Câu hỏi nhanh. Đoạn code sau in ra gì? x := 1; defer fmt.Println(x); x = 2

Tham số x được tính ngay lúc dòng defer chạy (lúc đó x = 1). Gán x = 2 sau đó không ảnh hưởng.

#Bài tập

FizzBuzz phiên bản Việt và đếm thời gian

In các số từ 1 đến 15, mỗi số một dòng, nhưng:

  • số chia hết cho cả 3 và 5: in Tròn
  • số chia hết cho 3: in Lẻ
  • số chia hết cho 5: in Chẵn
  • số còn lại: in chính số đó

Dùng switch không có giá trị phía sau. Dùng defer để in dòng "xong sau ..." khi hàm main kết thúc.

Gợi ý từng bước

  1. Vòng lặp từ 1 đến 15: for i := 1; i <= 15; i++.
  2. "Chia hết cho 3" viết là i%3 == 0 (% là phép chia lấy dư, giống JS).
  3. Chia hết cho cả 3 và 5 tức là chia hết cho 15. Đặt case này lên đầu: switch dừng ở case đúng đầu tiên, nếu để i%3 == 0 lên trước thì số 15 sẽ in "Lẻ".
  4. Đầu hàm main: start := time.Now(). Ngay sau đó defer một hàm in time.Since(start) (nhớ bọc trong func() { ... }(), xem phần cảnh báo ở trên).
Xem lời giải
main.go
package main

import (
    "fmt"
    "time"
)

func main() {
    start := time.Now() // ghi lại thời điểm bắt đầu

    // Hẹn: khi main kết thúc thì in thời gian đã trôi qua.
    // func() { ... }() = tạo một hàm rồi gọi nó. time.Since được tính lúc hàm này CHẠY (cuối main)
    defer func() {
        fmt.Println("xong sau", time.Since(start))
    }()

    for i := 1; i <= 15; i++ {
        switch {
        case i%15 == 0: // phải kiểm tra trước, xem gợi ý 3
            fmt.Println("Tròn")
        case i%3 == 0:
            fmt.Println("Lẻ")
        case i%5 == 0:
            fmt.Println("Chẵn")
        default:
            fmt.Println(i)
        }
    }
}

Hàm thử lại có chờ tăng dần

Gọi API của bên thứ ba (ngân hàng, gửi email) đôi khi lỗi tạm thời. Cách xử lý chuẩn là thử lại, mỗi lần chờ lâu gấp đôi lần trước: 100ms, 200ms, 400ms... Cách này tên là exponential backoff (bài 20 dùng lại).

Viết retry(attempts int, base time.Duration, fn func() error) error:

  • gọi fn(). Không lỗi thì trả nil luôn.
  • lỗi thì chờ (lần đầu chờ base, mỗi lần sau gấp đôi) rồi gọi lại.
  • gọi đủ attempts lần vẫn lỗi thì trả về lỗi cuối cùng.

Thử với một hàm giả lập lỗi 2 lần đầu, thành công lần thứ 3.

Gợi ý từng bước

  1. time.Duration là kiểu khoảng thời gian. Viết 100 * time.Millisecond là 100ms. time.Sleep(d) dừng chương trình trong khoảng d, giống await new Promise(r => setTimeout(r, 100)).
  2. Giữ một biến wait := base. Sau mỗi lần chờ: wait *= 2.
  3. Lần thử cuối mà vẫn lỗi thì đừng chờ nữa (chờ xong cũng không thử lại).
  4. Để kiểm tra, tạo hàm giả lập ngay trong main bằng closure, giống ví dụ retry trong bài.
Xem lời giải
main.go
package main

import (
    "errors"
    "fmt"
    "time"
)

func retry(attempts int, base time.Duration, fn func() error) error {
    var err error
    wait := base
    for i := range attempts { // i = 0, 1, ..., attempts-1
        err = fn()
        if err == nil {
            return nil // thành công: dừng ngay
        }
        if i < attempts-1 { // chưa phải lần cuối thì mới chờ
            fmt.Printf("lần %d lỗi (%v), chờ %v\n", i+1, err, wait)
            time.Sleep(wait)
            wait *= 2 // lần sau chờ gấp đôi
        }
    }
    // %w gói lỗi gốc vào lỗi mới (bài 07)
    return fmt.Errorf("hết %d lần thử: %w", attempts, err)
}

func main() {
    calls := 0
    flaky := func() error { // hàm giả lập: 2 lần đầu lỗi
        calls++
        if calls <= 2 {
            return errors.New("timeout")
        }
        return nil
    }

    err := retry(5, 100*time.Millisecond, flaky)
    fmt.Println("kết quả:", err, "| số lần gọi:", calls)

    // Trường hợp luôn lỗi
    err = retry(3, 10*time.Millisecond, func() error { return errors.New("máy chủ sập") })
    fmt.Println("kết quả:", err)
}

kết quả: <nil> | số lần gọi: 3
lần 1 lỗi (máy chủ sập), chờ 10ms
lần 2 lỗi (máy chủ sập), chờ 20ms
kết quả: hết 3 lần thử: máy chủ sập

Giải thích: flaky là một biến chứa hàm. Truyền flaky (không có ngoặc) là truyền chính cái hàm, để retry tự gọi. Viết flaky() là gọi nó ngay, rồi truyền kết quả, sai ý đồ. Giống hệt JS: retry(flaky) khác retry(flaky()).

Ngoài thực tế người ta còn thêm jitter (cộng một khoảng ngẫu nhiên vào thời gian chờ) để hàng nghìn client không cùng thử lại vào đúng một thời điểm. Bài viết "Exponential Backoff And Jitter" trên blog kiến trúc của AWS giải thích rất rõ điều này.
