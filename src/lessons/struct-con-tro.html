Struct: gom dữ liệu thành một kiểu

Go không có class. Thay vào đó là struct (dữ liệu) cộng method (hàm gắn với kiểu). Struct giống interface / type của TypeScript, nhưng là kiểu thật lúc chạy.

package main

import "fmt"

// Khai báo một KIỂU mới tên Student. Mỗi dòng: tên trường, rồi kiểu của trường
type Student struct {
    ID       int64
    FullName string
    ClassID  int64
    Scores   []float64 // slice điểm
}

func main() {
    // Tạo một giá trị kiểu Student. Trường không ghi (Scores) nhận zero value: nil
    s := Student{ID: 1, FullName: "Trần An", ClassID: 5}

    s.Scores = append(s.Scores, 9.5) // đọc / ghi trường bằng dấu chấm, giống JS
    fmt.Println(s.FullName, s.Scores)
    fmt.Printf("%+v\n", s) // %+v in kèm tên trường

    var empty Student // mọi trường là zero value
    fmt.Printf("%+v\n", empty)
}

Trần An [9.5]
{ID:1 FullName:Trần An ClassID:5 Scores:[9.5]}
{ID:0 FullName: ClassID:0 Scores:[]}

Khác object JS: struct có đúng các trường đã khai báo. Viết s.Phone = "..." là lỗi biên dịch vì Student không có trường Phone. Và không có trường nào là undefined: trường không gán có zero value.

Struct tag: nói cho JSON và database biết tên trường

Phần trong dấu backtick sau mỗi trường là tag, được các thư viện đọc để biết cách đổi sang JSON, tên cột database, quy tắc validate...

package main

import (
    "encoding/json"
    "fmt"
    "time"
)

type StudentDTO struct {
    ID       int64     `json:"id"`              // trong JSON tên là "id"
    FullName string    `json:"fullName"`
    Email    string    `json:"email,omitempty"` // rỗng thì bỏ hẳn khỏi JSON
    Password string    `json:"-"`               // không bao giờ xuất ra JSON
    JoinedAt time.Time `json:"joinedAt"`        // tự thành chuỗi ngày giờ chuẩn
    note     string    // viết thường: package json không thấy trường này
}

func main() {
    s := StudentDTO{
        ID:       1,
        FullName: "Trần An",
        Password: "bí mật",
        JoinedAt: time.Date(2026, 9, 5, 8, 0, 0, 0, time.UTC),
        note:     "ghi chú nội bộ",
    }
    b, _ := json.Marshal(s) // giống JSON.stringify(s)
    fmt.Println(string(b))
}

{"id":1,"fullName":"Trần An","joinedAt":"2026-09-05T08:00:00Z"}

Để ý kết quả: không có email (rỗng + omitempty), không có password (tag "-"), không có note (viết thường).

encoding/json chỉ đọc / ghi được trường viết hoa. Trường fullName string (viết thường) sẽ bị bỏ qua hoàn toàn mà không báo lỗi. Đây là lỗi số một của người mới: "sao API trả về {}?".

Con trỏ: địa chỉ của một giá trị

Trong JavaScript, object luôn được truyền theo tham chiếu. Trong Go, mọi thứ đều được truyền bằng cách sao chép, kể cả struct. Muốn hàm sửa được giá trị gốc, bạn truyền địa chỉ của nó: một con trỏ.

Hình dung bộ nhớ như dãy ô tủ, mỗi ô có số. Biến x nằm trong một ô. Con trỏ là tờ giấy ghi số ô đó. Ai có tờ giấy thì mở được đúng ô ấy để xem hoặc sửa.

package main

import "fmt"

func main() {
    x := 10
    p := &x // &x = "địa chỉ của x". p có kiểu *int, đọc là "con trỏ tới int"

    fmt.Println(p)  // in ra địa chỉ (mỗi máy mỗi khác)
    fmt.Println(*p) // *p = "giá trị tại địa chỉ p" = giá trị của x

    *p = 20         // ghi vào ô mà p trỏ tới, tức là sửa x
    fmt.Println(x)
}

0xc000012345
10
20

Dòng đầu là một địa chỉ bộ nhớ, máy bạn sẽ ra số khác. Nhớ hai ký hiệu: & = lấy địa chỉ, * = đi tới địa chỉ đó. Còn *int trong kiểu nghĩa là "con trỏ tới int".

package main

import "fmt"

type Student struct {
    FullName string
}

// Nhận Student: hàm nhận một BẢN SAO, sửa bản sao không ảnh hưởng bản gốc
func renameCopy(s Student) {
    s.FullName = "Bình"
}

// Nhận *Student: hàm nhận địa chỉ, sửa được bản gốc.
// Viết s.FullName là đủ, Go tự hiểu là (*s).FullName
func renamePtr(s *Student) {
    s.FullName = "Bình"
}

func main() {
    s := Student{FullName: "An"}

    renameCopy(s)
    fmt.Println("sau renameCopy:", s.FullName)

    renamePtr(&s) // truyền địa chỉ của s
    fmt.Println("sau renamePtr: ", s.FullName)
}

sau renameCopy: An
sau renamePtr:  Bình

Trong JS, function rename(s) { s.fullName = "Bình" } luôn sửa được object gốc. Go thì phải chọn: muốn hàm sửa được bản gốc thì nhận con trỏ.

Slice, map và channel chứa sẵn một con trỏ bên trong, nên truyền chúng vào hàm thì hàm sửa được nội dung (giống truyền mảng trong JS). Nhưng append trong hàm thì có thể không phản ánh ra ngoài (bài 04), nên hàm thêm phần tử thường trả về slice mới.

Go không có phép toán trên con trỏ (p++ như C), và bạn không phải tự giải phóng bộ nhớ. Hàm trả về con trỏ tới biến cục bộ là hoàn toàn an toàn: trình biên dịch tự quyết định đặt biến đó lên heap (gọi là escape analysis).

Method: hàm gắn với kiểu

Method là hàm có thêm một phần receiver đặt giữa func và tên hàm. Receiver giống this trong class JS, nhưng bạn tự đặt tên cho nó (thường là chữ cái đầu của kiểu).

package main

import "fmt"

type Rect struct{ W, H float64 } // struct một dòng: hai trường W và H cùng kiểu float64

// (r Rect) là receiver: method Area gắn với kiểu Rect, bên trong gọi r như "this"
func (r Rect) Area() float64 {
    return r.W * r.H
}

// (r *Rect): pointer receiver, nên method sửa được giá trị gốc
func (r *Rect) Scale(k float64) {
    r.W *= k
    r.H *= k
}

func main() {
    r := Rect{W: 2, H: 3}
    fmt.Println(r.Area()) // gọi method bằng dấu chấm, giống JS

    r.Scale(2) // Go tự đổi thành (&r).Scale(2) vì Scale cần con trỏ
    fmt.Println(r, r.Area())
}

6
{4 6} 24

So với TS: class Rect { area() { return this.w * this.h } }. Trong Go, dữ liệu (struct) và hành vi (method) viết tách nhau, nhưng gọi thì giống hệt: r.Area().

Value receiver hay pointer receiver?

Dùng pointer receiver (r *T) khiDùng value receiver (r T) khi
Method cần sửa giá trịKiểu nhỏ, không đổi (Point, Money, time.Time)
Struct lớn (tránh sao chép mỗi lần gọi)Bạn muốn mỗi giá trị là độc lập
Struct chứa thứ không được sao chép: sync.Mutex, kết nối...

Quy tắc thực tế: một kiểu dùng một loại receiver cho mọi method. Với các kiểu "dịch vụ" ở backend (UserService, Repository, Handler) luôn dùng pointer receiver.

Hàm khởi tạo New...

Go không có constructor. Thay vào đó là một hàm thường, tên bắt đầu bằng New, tạo giá trị với mặc định hợp lý và trả về con trỏ:

package main

import (
    "fmt"
    "time"
)

type Server struct {
    addr    string
    timeout time.Duration
}

// Giống constructor(addr) { this.addr = addr; this.timeout = 10_000 }
func NewServer(addr string) *Server {
    return &Server{ // &Student{...}: tạo giá trị rồi lấy địa chỉ luôn
        addr:    addr,
        timeout: 10 * time.Second, // giá trị mặc định
    }
}

func main() {
    srv := NewServer(":8080")
    fmt.Println(srv.addr, srv.timeout)
}

:8080 10s

Hàm NewX là quy ước, không phải cú pháp đặc biệt. Ở bài 13, NewServer sẽ nhận thêm kết nối database, logger... để ghép các thành phần của server lại (dependency injection).

Dùng con trỏ để biết "có gửi hay không"

Quay lại bài toán ở bài 02: API cập nhật một phần (PATCH). Client chỉ gửi trường nào muốn đổi.

package main

import (
    "encoding/json"
    "fmt"
)

type UpdateStudentReq struct {
    FullName *string  `json:"fullName"` // con trỏ: nil = client không gửi trường này
    Score    *float64 `json:"score"`
}

func main() {
    bodies := []string{`{"score": 0}`, `{}`, `{"fullName": "Bình", "score": 9}`}

    for _, body := range bodies {
        var req UpdateStudentReq
        json.Unmarshal([]byte(body), &req) // giống JSON.parse, ghi kết quả vào req

        fmt.Print(body, " -> ")
        if req.FullName != nil {
            fmt.Print("đổi tên thành ", *req.FullName, ". ")
        }
        if req.Score != nil {
            fmt.Print("đổi điểm thành ", *req.Score, ". ")
        }
        if req.FullName == nil && req.Score == nil {
            fmt.Print("không đổi gì.")
        }
        fmt.Println()
    }
}

{"score": 0} -> đổi điểm thành 0. 
{} -> không đổi gì.
{"fullName": "Bình", "score": 9} -> đổi tên thành Bình. đổi điểm thành 9.

Nếu Score là float64 thường, hai body đầu đều cho Score = 0 và bạn sẽ lỡ tay xoá điểm của học sinh. json.Unmarshal nhận &req (con trỏ) chính vì nó cần ghi vào req của bạn.

Thư viện của Google cho nhiều API (ví dụ google.golang.org/api) và AWS SDK for Go dùng đúng cách này: trường tuỳ chọn là con trỏ, kèm các hàm trợ giúp kiểu aws.String("x") để lấy con trỏ từ một giá trị.

So sánh struct

Struct mà mọi trường đều so sánh được thì dùng được == và làm khoá của map. Struct có slice hoặc map bên trong thì không.

package main

import "fmt"

type Point struct{ X, Y int }

func main() {
    fmt.Println(Point{1, 2} == Point{1, 2}) // so từng trường. Trong JS {x:1} === {x:1} là false

    visited := map[Point]bool{{0, 0}: true} // struct làm khoá của map
    fmt.Println(visited[Point{0, 0}], visited[Point{5, 5}])
}

Bài tập

Giỏ hàng

Tạo kiểu Cart (giỏ hàng) chứa danh sách Item, mỗi item có mã sản phẩm, giá, số lượng. Viết ba method:

  • Add(item Item): thêm vào giỏ. Sản phẩm đã có trong giỏ thì cộng dồn số lượng, không thêm dòng mới.
  • Remove(productID int64): bỏ sản phẩm khỏi giỏ.
  • Total() int64: tổng tiền.

Thử: thêm 2 cuốn vở giá 10.000đ, thêm 1 bút giá 5.000đ, thêm 1 cuốn vở nữa, in tổng. Bỏ bút, in tổng. Kết quả mong muốn:

số dòng: 2
tổng: 35000
sau khi bỏ bút: 30000

Gợi ý từng bước

  1. Khai báo type Item struct { ProductID int64; Price int64; Qty int } và type Cart struct { Items []Item }.
  2. Add và Remove phải sửa giỏ hàng, nên dùng pointer receiver: func (c *Cart) Add(it Item).
  3. Trong Add, duyệt c.Items bằng chỉ số (for i := range c.Items). Gặp cùng ProductID thì c.Items[i].Qty += it.Qty rồi return. Không gặp thì append. Đừng sửa qua biến của for _, x := range: đó là bản sao (xem câu hỏi ở trên).
  4. Remove: dùng slices.DeleteFunc(c.Items, func(it Item) bool { ... }), giống items.filter(...) nhưng giữ lại phần tử mà hàm trả về false.
  5. Total: cộng Price * Qty. Qty là int, Price là int64, nên phải đổi kiểu: int64(it.Qty).
Xem lời giải 
package main

import (
    "fmt"
    "slices"
)

type Item struct {
    ProductID int64
    Price     int64 // đồng
    Qty       int
}

type Cart struct {
    Items []Item
}

func (c *Cart) Add(it Item) {
    for i := range c.Items {
        if c.Items[i].ProductID == it.ProductID {
            c.Items[i].Qty += it.Qty // sửa qua chỉ số, không qua biến range
            return
        }
    }
    c.Items = append(c.Items, it)
}

func (c *Cart) Remove(id int64) {
    c.Items = slices.DeleteFunc(c.Items, func(it Item) bool { return it.ProductID == id })
}

func (c *Cart) Total() int64 {
    var t int64
    for _, it := range c.Items { // chỉ đọc nên dùng bản sao cũng được
        t += it.Price * int64(it.Qty)
    }
    return t
}

func main() {
    cart := &Cart{} // giỏ rỗng. &: lấy con trỏ, vì các method dùng *Cart

    cart.Add(Item{ProductID: 1, Price: 10_000, Qty: 2}) // 2 cuốn vở
    cart.Add(Item{ProductID: 2, Price: 5_000, Qty: 1})  // 1 bút
    cart.Add(Item{ProductID: 1, Price: 10_000, Qty: 1}) // thêm 1 vở: cộng dồn thành 3

    fmt.Println("số dòng:", len(cart.Items))
    fmt.Println("tổng:", cart.Total())

    cart.Remove(2)
    fmt.Println("sau khi bỏ bút:", cart.Total())
}

số dòng: 2
tổng: 35000
sau khi bỏ bút: 30000

Giải thích: 3 vở × 10.000 + 1 bút × 5.000 = 35.000. "số dòng: 2" chứng tỏ lần thêm vở thứ hai được cộng dồn chứ không thêm dòng mới. Total không sửa gì, nhưng vẫn dùng pointer receiver để cả kiểu dùng một loại receiver. Nhắc lại bài 00: khi làm thật, Price phải lấy từ database lúc thanh toán, không tin giá trong giỏ hàng client gửi lên.
