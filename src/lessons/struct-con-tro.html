Struct: gom dữ liệu thành một kiểu

Go không có class. Thay vào đó là struct (dữ liệu) cộng method (hàm gắn với kiểu). Struct giống interface / type của TypeScript, nhưng là kiểu thật lúc chạy.

type Student struct {
    ID       int64
    FullName string
    ClassID  int64
    Scores   []float64
    JoinedAt time.Time
}

// Tạo giá trị
s := Student{ID: 1, FullName: "Trần An", ClassID: 5}
s.Scores = append(s.Scores, 9.5)
fmt.Println(s.FullName)

var empty Student      // mọi trường là zero value: 0, "", nil, thời điểm 0

Struct tag: nói cho JSON và database biết tên trường

Phần trong dấu backtick sau mỗi trường là tag, được các thư viện đọc để biết cách đổi sang JSON, tên cột database, quy tắc validate...

type StudentDTO struct {
    ID       int64     `json:"id"`
    FullName string    `json:"fullName"`
    Email    string    `json:"email,omitempty"` // rỗng thì bỏ khỏi JSON
    Password string    `json:"-"`               // không bao giờ xuất ra JSON
    JoinedAt time.Time `json:"joinedAt"`        // tự thành chuỗi RFC 3339
}

encoding/json chỉ đọc / ghi được trường viết hoa. Trường fullName string (viết thường) sẽ bị bỏ qua hoàn toàn mà không báo lỗi. Đây là lỗi số một của người mới: "sao API trả về {}?".

Con trỏ: địa chỉ của một giá trị

Trong JavaScript, object luôn được truyền theo tham chiếu. Trong Go, mọi thứ đều được truyền bằng cách sao chép, kể cả struct. Muốn hàm sửa được giá trị gốc, bạn truyền địa chỉ của nó: một con trỏ.

x := 10
p := &x        // &: lấy địa chỉ. p có kiểu *int ("con trỏ tới int")
fmt.Println(*p) // *: đọc giá trị tại địa chỉ → 10
*p = 20         // ghi qua con trỏ
fmt.Println(x)  // 20

func renameCopy(s Student)   { s.FullName = "Bình" } // sửa bản sao, vô ích
func renamePtr(s *Student)   { s.FullName = "Bình" } // Go tự hiểu s.FullName = (*s).FullName

s := Student{FullName: "An"}
renameCopy(s)
fmt.Println(s.FullName) // An
renamePtr(&s)
fmt.Println(s.FullName) // Bình

Slice, map và channel chứa sẵn một con trỏ bên trong, nên truyền chúng vào hàm thì hàm sửa được nội dung (giống truyền mảng trong JS). Nhưng append trong hàm thì có thể không phản ánh ra ngoài (bài 04), nên hàm thêm phần tử thường trả về slice mới.

Go không có phép toán trên con trỏ (p++ như C), và bạn không phải tự giải phóng bộ nhớ. Hàm trả về con trỏ tới biến cục bộ là hoàn toàn an toàn: trình biên dịch tự quyết định đặt biến đó lên heap (gọi là escape analysis).

nil pointer: lỗi runtime hay gặp nhất

var u *Student          // nil
fmt.Println(u.FullName) // panic: runtime error: invalid memory address or nil pointer dereference

Hàm trả về con trỏ thì phải nói rõ khi nào trả nil, và người gọi phải kiểm tra. Mẫu chuẩn: hàm "tìm" trả về (*T, error), nếu không tìm thấy thì trả lỗi riêng thay vì nil, nil.

Method: hàm gắn với kiểu

type Rect struct{ W, H float64 }

// receiver (r Rect) đứng trước tên hàm
func (r Rect) Area() float64 {
    return r.W * r.H
}

// pointer receiver: method sửa được giá trị gốc
func (r *Rect) Scale(k float64) {
    r.W *= k
    r.H *= k
}

r := Rect{W: 2, H: 3}
r.Scale(2)          // Go tự lấy &r khi gọi
fmt.Println(r.Area()) // 24

Value receiver hay pointer receiver?

Dùng pointer receiver (r *T) khiDùng value receiver (r T) khi
Method cần sửa giá trịKiểu nhỏ, không đổi (Point, Money, time.Time)
Struct lớn (tránh sao chép mỗi lần gọi)Bạn muốn mỗi giá trị là độc lập
Struct chứa thứ không được sao chép: sync.Mutex, kết nối...

Quy tắc thực tế: một kiểu dùng một loại receiver cho mọi method. Với các kiểu "dịch vụ" ở backend (UserService, Repository, Handler) luôn dùng pointer receiver.

Hàm khởi tạo New...

type Server struct {
    addr    string
    timeout time.Duration
    db      *pgxpool.Pool
}

func NewServer(addr string, db *pgxpool.Pool) *Server {
    return &Server{
        addr:    addr,
        timeout: 10 * time.Second, // giá trị mặc định
        db:      db,
    }
}

Hàm NewX là quy ước, không phải cú pháp đặc biệt. Bạn sẽ dùng nó để ghép các thành phần của server lại ở bài 13 (dependency injection).

Bài tập

Giỏ hàng

Tạo Cart chứa danh sách Item{ProductID int64; Price int64; Qty int}. Viết method Add(item Item) (sản phẩm đã có thì cộng dồn số lượng), Remove(productID int64), Total() int64. Chọn đúng loại receiver.

Xem lời giải 
type Item struct {
    ProductID int64
    Price     int64 // đồng
    Qty       int
}

type Cart struct {
    Items []Item
}

func (c *Cart) Add(it Item) {
    for i := range c.Items {
        if c.Items[i].ProductID == it.ProductID {
            c.Items[i].Qty += it.Qty // sửa qua chỉ số, không qua biến range
            return
        }
    }
    c.Items = append(c.Items, it)
}

func (c *Cart) Remove(id int64) {
    c.Items = slices.DeleteFunc(c.Items, func(it Item) bool { return it.ProductID == id })
}

func (c *Cart) Total() int64 {
    var t int64
    for _, it := range c.Items {
        t += it.Price * int64(it.Qty)
    }
    return t
}

Total không sửa gì, nhưng vẫn dùng pointer receiver để cả kiểu dùng một loại receiver. Nhắc lại bài 00: khi làm thật, Price phải lấy từ database lúc thanh toán, không tin giá trong giỏ hàng client gửi lên.
