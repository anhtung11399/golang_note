Lưu mật khẩu: băm chậm, có muối

Không bao giờ lưu mật khẩu, kể cả đã mã hoá (mã hoá thì giải mã được). Lưu giá trị băm bằng thuật toán chuyên cho mật khẩu: cố tình chậm và tốn bộ nhớ, để kẻ trộm database không thể thử hàng tỷ mật khẩu mỗi giây.

Thuật toánDùng cho mật khẩu?
MD5, SHA-1, SHA-256 (trần)Không. Quá nhanh: card đồ hoạ thử được hàng tỷ lần mỗi giây
Argon2idCó. OWASP khuyến nghị dùng đầu tiên
bcryptCó. Rất phổ biến, đơn giản. Chỉ dùng 72 byte đầu của mật khẩu
scrypt, PBKDF2Chấp nhận được (PBKDF2 khi cần chuẩn FIPS)
import "golang.org/x/crypto/bcrypt"

func HashPassword(pw string) (string, error) {
    if len(pw) < 8 || len(pw) > 72 { // bcrypt chỉ nhận tối đa 72 byte
        return "", &ValidationError{Field: "password", Message: "Mật khẩu từ 8 đến 72 ký tự"}
    }
    b, err := bcrypt.GenerateFromPassword([]byte(pw), 12) // cost 12: mỗi lần băm cỡ vài trăm ms
    return string(b), err
}

func CheckPassword(hash, pw string) bool {
    return bcrypt.CompareHashAndPassword([]byte(hash), []byte(pw)) == nil
}

Chuỗi băm bcrypt đã chứa sẵn muối (salt) ngẫu nhiên và cost: $2a$12$R9h/cIPz0gi.URNNX3kh2O.... Hai người cùng mật khẩu 123456 vẫn có hai chuỗi băm khác nhau.

Đăng nhập phải trả cùng một thông báo cho "sai email" và "sai mật khẩu" ("Email hoặc mật khẩu không đúng"), nếu không kẻ tấn công dò được email nào đã đăng ký. Và nhớ giới hạn tần suất đăng nhập (bài 17): băm chậm không cứu được mật khẩu 12345678 nếu kẻ tấn công được thử không giới hạn.

Nhiều vụ rò rỉ lớn bị khuếch đại vì mật khẩu được băm bằng thuật toán nhanh. Vụ LinkedIn năm 2012 là ví dụ hay được nhắc: mật khẩu băm SHA-1 không muối, sau đó phần lớn bị bẻ khoá. Ngày nay, nhiều sản phẩm chọn không tự lưu mật khẩu nữa mà cho đăng nhập bằng Google / Apple, magic link qua email, hoặc passkey.

Phiên đăng nhập (session)

Sau khi xác thực xong, server cần "nhớ" người dùng cho các request sau. Cách truyền thống và vẫn rất tốt cho web: session token ngẫu nhiên trong cookie.

actors: [fe] Trình duyệt, [go] API, [db] Database Trình duyệt -> API: POST /login (email, mật khẩu) API -> Database: kiểm tra mật khẩu note API: tạo token 32 byte ngẫu nhiên (crypto/rand) API -> Database: lưu sha256(token), user_id, hạn API --> Trình duyệt: Set-Cookie: session=token; HttpOnly; Secure; SameSite=Lax == các request sau == Trình duyệt -> API: GET /me (trình duyệt tự gửi cookie) API -> Database: tìm sha256(token) còn hạn API --> Trình duyệt: 200 {user} 
func NewSessionToken() (token string, hash []byte, err error) {
    b := make([]byte, 32)
    if _, err := rand.Read(b); err != nil { // crypto/rand, KHÔNG phải math/rand
        return "", nil, err
    }
    token = base64.RawURLEncoding.EncodeToString(b)
    h := sha256.Sum256([]byte(token))
    return token, h[:], nil // gửi token cho client, chỉ lưu hash vào database
}

func SetSessionCookie(w http.ResponseWriter, token string, ttl time.Duration) {
    http.SetCookie(w, &http.Cookie{
        Name:     "__Host-session", // tiền tố __Host-: bắt buộc Secure, Path=/, không Domain
        Value:    token,
        Path:     "/",
        MaxAge:   int(ttl.Seconds()),
        HttpOnly: true,                 // JavaScript không đọc được → XSS không lấy được token
        Secure:   true,                 // chỉ gửi qua HTTPS
        SameSite: http.SameSiteLaxMode, // hạn chế gửi kèm request từ trang khác (CSRF)
    })
}

Vì sao lưu băm của token? Nếu database bị lộ (bản sao lưu, log), kẻ tấn công cũng không dùng được các phiên đang hoạt động.

  • Đăng xuất: xoá dòng phiên trong database. Hiệu lực ngay.
  • Đổi mật khẩu: xoá mọi phiên khác của người đó.
  • Hạn phiên: ví dụ 30 ngày, gia hạn khi người dùng còn hoạt động.

Lưu token trong localStorage rất tiện ở frontend, nhưng bất kỳ đoạn script nào chạy được trên trang (một thư viện bị chiếm quyền, một lỗi XSS) đều đọc được nó. Cookie HttpOnly thì JavaScript không đọc được. Với ứng dụng web cùng tên miền với API, cookie là lựa chọn an toàn hơn.

type ctxUserKey struct{}

func (a *Auth) Middleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        c, err := r.Cookie("__Host-session")

func RequireUser(next http.HandlerFunc) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        if _, ok := r.Context().Value(ctxUserKey{}).(User); !ok {
            WriteJSON(w, http.StatusUnauthorized, errBody("UNAUTHENTICATED", "Vui lòng đăng nhập"))

        }
        next(w, r)
    }
}

JWT: khi nào nên, khi nào không

JWT (JSON Web Token) là một chuỗi gồm 3 phần header.payload.signature. Payload chứa thông tin (user id, vai trò, hạn), chữ ký chứng minh server đã tạo ra nó. Server kiểm chữ ký là tin payload, không cần tra database.

Session trong databaseJWT

Mỗi request tra databaseCó (cache được bằng Redis)Không

Hợp vớiWeb app thông thườngGiao tiếp giữa các dịch vụ, token ngắn hạn, hệ thống nhiều bên (OAuth, OIDC)

Lỗi JWT hay gặp: chấp nhận thuật toán none hoặc để token tự chọn thuật toán; khoá ký yếu; hạn quá dài (vài tháng); nhét dữ liệu nhạy cảm vào payload (payload chỉ được mã hoá base64, ai cũng đọc được, không phải mã hoá bí mật). Nếu dùng JWT: thư viện uy tín (golang-jwt/jwt/v5), cố định thuật toán khi kiểm, hạn ngắn (5 đến 15 phút) kèm refresh token lưu ở server.

Đăng nhập bằng Google (OAuth 2.0 / OpenID Connect)

Ứng dụng hiện đại thường để Google / Apple xác thực, bạn khỏi lưu mật khẩu. Luồng an toàn cho web là Authorization Code + PKCE, chạy ở phía server:

actors: [fe] Trình duyệt, [go] API của bạn, [ext] Google Trình duyệt -> API của bạn: GET /auth/google note API của bạn: tạo state + code_verifier, lưu vào cookie ký API của bạn --> Trình duyệt: 302 tới accounts.google.com (state, code_challenge) Trình duyệt -> Google: người dùng chọn tài khoản, đồng ý Google --> Trình duyệt: 302 về /auth/callback?code=...&state=... Trình duyệt -> API của bạn: GET /auth/callback note API của bạn: so state với cookie (chống giả mạo) API của bạn -> Google: đổi code + code_verifier + client_secret lấy id_token Google --> API của bạn: id_token (email, sub) note API của bạn: kiểm chữ ký, aud, hạn → tìm / tạo user theo sub → tạo session API của bạn --> Trình duyệt: Set-Cookie session, chuyển về trang chủ

Package golang.org/x/oauth2 lo phần lớn luồng này (có hỗ trợ PKCE). Định danh người dùng là trường sub của Google (không đổi), không phải email (người dùng có thể đổi email).

Theo quyền sở hữu: nơi lỗ hổng hay nằm

Vai trò "giáo viên" cho phép sửa lớp, nhưng chỉ lớp của mình. Kiểm tra này không làm ở middleware được vì phụ thuộc dữ liệu. Cách an toàn nhất: đưa người dùng hiện tại vào mọi câu truy vấn.

Mỗi quy tắc phân quyền cần một test: tạo hai người dùng, người A tạo dữ liệu, người B thử đọc / sửa / xoá dữ liệu đó qua mọi endpoint, phải nhận 403/404. Nhiều đội gom các test này thành một bộ riêng và chạy ở mọi lần thay đổi.

Một mẫu giúp không quên: hàm tầng store đều nhận người gọi làm tham số, như ClassOf(ctx, teacherID, classID) thay vì Class(ctx, classID). Không có hàm nào lấy dữ liệu theo id trần để người viết handler vô tình dùng.

CSRF khi dùng cookie

Trình duyệt tự gửi cookie kèm request, kể cả request do một trang web khác tạo ra (form ẩn tự submit). Đó là tấn công CSRF.

  • SameSite=Lax: cookie không đi kèm POST / PUT / DELETE xuất phát từ trang khác. Đã chặn được phần lớn.
  • Kiểm header Origin (hoặc Sec-Fetch-Site) của mọi request thay đổi dữ liệu: phải là tên miền của bạn.
  • Từ Go 1.25, net/http có sẵn http.CrossOriginProtection làm việc này dựa trên Sec-Fetch-Site và Origin.
  • API chỉ nhận Content-Type: application/json cũng khó bị tạo từ form HTML thường.
- Không cần, vai trò phụ huynh đã đủ - Kiểm tra bé 123 có tồn tại + Kiểm tra bé 123 là con của chính phụ huynh này, tốt nhất là ngay trong câu truy vấn ? Vai trò không thay thế được quyền sở hữu. Đổi 123 thành 124 là xem được điểm con nhà khác nếu thiếu kiểm tra này: lỗi BOLA, bài 19.

Bài tập

Đăng ký, đăng nhập, đăng xuất

Viết API ghi chú có tài khoản, lưu trong Postgres:

  • POST /register, POST /login, POST /logout, GET /me.
  • Đăng nhập sai 5 lần trong 15 phút cho cùng một email thì trả 429.
  • GET /notes, POST /notes, GET /notes/{id}, DELETE /notes/{id}: mỗi người chỉ thấy và xoá được ghi chú của mình.

Gợi ý từng bước

  1. Ba bảng: app_users (email UNIQUE, password_hash), sessions (token_hash, user_id, expires_at), notes (user_id, text). Đặt tên app_users để không đụng bảng users của bài 14 nếu dùng chung database.
  2. Đăng ký: chuẩn hoá email về chữ thường, kiểm độ dài mật khẩu, băm bằng bcrypt, INSERT. Trùng email thì Postgres trả lỗi 23505, đổi thành 409 (bài 15). Đăng ký xong tạo phiên luôn.
  3. Đăng nhập: tìm theo email, so mật khẩu bằng bcrypt.CompareHashAndPassword. Không có email và sai mật khẩu trả cùng một câu.
  4. Phiên: token 32 byte từ crypto/rand, đặt vào cookie, database chỉ lưu SHA-256 của token. Middleware đọc cookie, tìm phiên còn hạn, đưa User vào ctx (bài 10).
  5. Ghi chú: mọi câu SQL có AND user_id = $n với $n là người đang đăng nhập.
  6. Giới hạn đăng nhập sai: một map email -> danh sách thời điểm sai có mutex (bài 09) là đủ để làm bài. Nhiều bản server thì dùng Redis như bài 17.
Xem lời giải

Chuẩn bị: dùng Postgres của bài 14, dán lược đồ này vào psql:

CREATE TABLE app_users (
    id            bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email         text NOT NULL UNIQUE,
    password_hash text NOT NULL,
    created_at    timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE sessions (
    token_hash  bytea PRIMARY KEY,                 -- sha256 của token, không lưu token thật
    user_id     bigint NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
    expires_at  timestamptz NOT NULL
);

CREATE TABLE notes (
    id          bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id     bigint NOT NULL REFERENCES app_users(id) ON DELETE CASCADE,
    text        text NOT NULL CHECK (char_length(text) BETWEEN 1 AND 500),
    created_at  timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX notes_user_idx ON notes (user_id, id);

package main

import (
    "context"
    "crypto/rand"
    "crypto/sha256"
    "encoding/base64"
    "errors"
    "net/http"
    "strings"
    "sync"

    "github.com/jackc/pgx/v5"

const (
    cookieName = "__Host-session"
    sessionTTL = 30 * 24 * time.Hour
)

type User struct {
    ID    int64  `json:"id"`
    Email string `json:"email"`
}

type ctxUserKey struct{}

func userFrom(ctx context.Context) (User, bool) {
    u, ok := ctx.Value(ctxUserKey{}).(User)
    return u, ok
}

func hashToken(token string) []byte {
    h := sha256.Sum256([]byte(token))
    return h[:]
}

// newSession tạo token ngẫu nhiên, lưu BẢN BĂM vào database, trả token thật để đặt vào cookie
func (a *App) newSession(ctx context.Context, userID int64) (string, error) {
    b := make([]byte, 32)
    if _, err := rand.Read(b); err != nil { // crypto/rand: không đoán được
        return "", err
    }
    token := base64.RawURLEncoding.EncodeToString(b)
    _, err := a.db.Exec(ctx,
        `INSERT INTO sessions (token_hash, user_id, expires_at) VALUES ($1, $2, $3)`,
        hashToken(token), userID, time.Now().Add(sessionTTL))
    return token, err
}

func setSessionCookie(w http.ResponseWriter, token string, maxAge int) {
    http.SetCookie(w, &http.Cookie{
        Name:     cookieName,
        Value:    token,
        Path:     "/",
        MaxAge:   maxAge, // số âm: xoá cookie
        HttpOnly: true,
        Secure:   true, // trình duyệt và curl coi localhost là "an toàn" nên vẫn chạy được khi thử trên máy
        SameSite: http.SameSiteLaxMode,
    })
}

// authMiddleware: có cookie hợp lệ thì đưa User vào ctx. Không có thì vẫn cho đi tiếp
func (a *App) authMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        if c, err := r.Cookie(cookieName); err == nil {
            var u User
            err := a.db.QueryRow(r.Context(), `
                SELECT u.id, u.email FROM sessions s JOIN app_users u ON u.id = s.user_id
                WHERE s.token_hash = $1 AND s.expires_at > now()`, hashToken(c.Value)).Scan(&u.ID, &u.Email)
            if err == nil {
                r = r.WithContext(context.WithValue(r.Context(), ctxUserKey{}, u))
            }
        }
        next.ServeHTTP(w, r)
    })
}

// requireUser: route nào cần đăng nhập thì bọc bằng hàm này
func requireUser(next func(http.ResponseWriter, *http.Request, User)) http.HandlerFunc {
    return func(w http.ResponseWriter, r *http.Request) {
        u, ok := userFrom(r.Context())
        if !ok {
            writeErr(w, http.StatusUnauthorized, "Vui lòng đăng nhập")
            return
        }
        next(w, r, u)
    }
}

// loginLimiter: tối đa 5 lần đăng nhập SAI trong 15 phút cho mỗi email.
// Lưu trong bộ nhớ cho gọn. Chạy nhiều bản server thì chuyển sang Redis (bài 17)
type loginLimiter struct {
    mu    sync.Mutex
    fails map[string][]time.Time
}

func (l *loginLimiter) blocked(email string) bool {
    l.mu.Lock()
    defer l.mu.Unlock()
    recent := l.fails[email][:0]
    for _, t := range l.fails[email] {
        if time.Since(t) < 15*time.Minute {
            recent = append(recent, t)
        }
    }
    l.fails[email] = recent
    return len(recent) >= 5
}

func (l *loginLimiter) fail(email string) {
    l.mu.Lock()
    defer l.mu.Unlock()
    l.fails[email] = append(l.fails[email], time.Now())
}

type credentials struct {
    Email    string `json:"email"`
    Password string `json:"password"`
}

func (c *credentials) normalize() {
    c.Email = strings.ToLower(strings.TrimSpace(c.Email))
}

func (a *App) register(w http.ResponseWriter, r *http.Request) {
    var in credentials
    if !decode(w, r, &in) {
        return
    }
    in.normalize()
    if !strings.Contains(in.Email, "@") || len(in.Email) > 254 {
        writeErr(w, http.StatusBadRequest, "Email không hợp lệ")
        return
    }
    if len(in.Password) < 8 || len(in.Password) > 72 { // bcrypt chỉ dùng 72 byte đầu
        writeErr(w, http.StatusBadRequest, "Mật khẩu từ 8 đến 72 ký tự")
        return
    }
    hash, err := bcrypt.GenerateFromPassword([]byte(in.Password), 12)
    if err != nil {
        a.internal(w, r, err)
        return
    }
    var u User
    err = a.db.QueryRow(r.Context(),
        `INSERT INTO app_users (email, password_hash) VALUES ($1, $2) RETURNING id, email`,
        in.Email, string(hash)).Scan(&u.ID, &u.Email)
    var pgErr *pgconn.PgError
    if errors.As(err, &pgErr) && pgErr.Code == "23505" { // UNIQUE(email): không SELECT kiểm tra trước
        writeErr(w, http.StatusConflict, "Email đã được dùng")
        return
    }
    if err != nil {
        a.internal(w, r, err)
        return
    }
    a.startSession(w, r, u, http.StatusCreated)
}

func (a *App) login(w http.ResponseWriter, r *http.Request) {
    var in credentials
    if !decode(w, r, &in) {
        return
    }
    in.normalize()
    if a.limiter.blocked(in.Email) {
        w.Header().Set("Retry-After", "900")
        writeErr(w, http.StatusTooManyRequests, "Thử sai quá nhiều lần, vui lòng thử lại sau 15 phút")
        return
    }
    var u User
    var hash string
    err := a.db.QueryRow(r.Context(),
        `SELECT id, email, password_hash FROM app_users WHERE email = $1`, in.Email).Scan(&u.ID, &u.Email, &hash)
    if err != nil && !errors.Is(err, pgx.ErrNoRows) {
        a.internal(w, r, err)
        return
    }
    // Sai email hay sai mật khẩu: CÙNG một câu trả lời, để không dò được email nào đã đăng ký
    if err != nil || bcrypt.CompareHashAndPassword([]byte(hash), []byte(in.Password)) != nil {
        a.limiter.fail(in.Email)
        writeErr(w, http.StatusUnauthorized, "Email hoặc mật khẩu không đúng")
        return
    }
    a.startSession(w, r, u, http.StatusOK)
}

func (a *App) startSession(w http.ResponseWriter, r *http.Request, u User, status int) {
    token, err := a.newSession(r.Context(), u.ID)
    if err != nil {
        a.internal(w, r, err)
        return
    }
    setSessionCookie(w, token, int(sessionTTL.Seconds()))
    writeJSON(w, status, u)
}

func (a *App) logout(w http.ResponseWriter, r *http.Request) {
    if c, err := r.Cookie(cookieName); err == nil {
        a.db.Exec(r.Context(), `DELETE FROM sessions WHERE token_hash = $1`, hashToken(c.Value))
    }
    setSessionCookie(w, "", -1)
    w.WriteHeader(http.StatusNoContent)
}

func (a *App) me(w http.ResponseWriter, r *http.Request, u User) {
    writeJSON(w, http.StatusOK, u)
}

func (a *App) listNotes(w http.ResponseWriter, r *http.Request, u User) {
    rows, err := a.db.Query(r.Context(),
        `SELECT id, text, created_at FROM notes WHERE user_id = $1 ORDER BY id`, u.ID)
    if err != nil {
        a.internal(w, r, err)
        return
    }
    defer rows.Close()
    out := []Note{}
    for rows.Next() {
        var n Note
        if err := rows.Scan(&n.ID, &n.Text, &n.CreatedAt); err != nil {
            a.internal(w, r, err)
            return
        }
        out = append(out, n)
    }
    writeJSON(w, http.StatusOK, out)
}

func (a *App) createNote(w http.ResponseWriter, r *http.Request, u User) {
    var in struct {
        Text string `json:"text"`
    }
    if !decode(w, r, &in) {
        return
    }
    in.Text = strings.TrimSpace(in.Text)
    if n := utf8.RuneCountInString(in.Text); n == 0 || n > 500 {
        writeErr(w, http.StatusBadRequest, "Nội dung từ 1 đến 500 ký tự")
        return
    }
    n := Note{Text: in.Text}
    err := a.db.QueryRow(r.Context(),
        `INSERT INTO notes (user_id, text) VALUES ($1, $2) RETURNING id, created_at`, u.ID, in.Text,
    ).Scan(&n.ID, &n.CreatedAt)
    if err != nil {
        a.internal(w, r, err)
        return
    }
    writeJSON(w, http.StatusCreated, n)
}

func (a *App) getNote(w http.ResponseWriter, r *http.Request, u User) {
    id, _ := strconv.ParseInt(r.PathValue("id"), 10, 64)
    var n Note
    err := a.db.QueryRow(r.Context(),
        `SELECT id, text, created_at FROM notes WHERE id = $1 AND user_id = $2`, id, u.ID,
    ).Scan(&n.ID, &n.Text, &n.CreatedAt)
    if err != nil { // không có, HOẶC có nhưng của người khác: cùng trả 404
        writeErr(w, http.StatusNotFound, "Không tìm thấy")
        return
    }
    writeJSON(w, http.StatusOK, n)
}

func (a *App) deleteNote(w http.ResponseWriter, r *http.Request, u User) {
    id, _ := strconv.ParseInt(r.PathValue("id"), 10, 64)
    tag, err := a.db.Exec(r.Context(), `DELETE FROM notes WHERE id = $1 AND user_id = $2`, id, u.ID)
    if err != nil {
        a.internal(w, r, err)
        return
    }
    if tag.RowsAffected() == 0 {
        writeErr(w, http.StatusNotFound, "Không tìm thấy")
        return
    }
    w.WriteHeader(http.StatusNoContent)
}

Giải thích từng điểm:

  • Email Lan@Gmail.com được lưu thành lan@gmail.com, nên lần đăng ký thứ hai (chữ thường) bị coi là trùng.
  • Bình có id 3 chứ không phải 2: lần đăng ký trùng email đã lấy mất số 2 rồi mới bị UNIQUE từ chối. Bộ đếm tự tăng không quay lại, id có "lỗ" là bình thường.
  • Bình đọc và xoá ghi chú 1 của Lan đều nhận 404, như thể ghi chú không tồn tại. Đó là nhờ AND user_id = $2 trong câu SQL.
  • Sai email hay sai mật khẩu đều ra cùng một câu, nên không dò được email nào đã có tài khoản.
  • Sau 5 lần sai, kể cả nhập đúng mật khẩu cũng bị 429: kẻ dò mật khẩu không biết lần nào là đúng. Bộ đếm nằm trong bộ nhớ nên tắt server là mất, và mỗi bản server đếm riêng (xem bài 17).
  • Lệnh đăng xuất không dùng -c nên file lan.txt vẫn giữ token cũ. Gửi lại token đó vẫn bị 401: phiên đã bị xoá ở phía server, đây là ưu điểm của session so với JWT.
  • Cookie có Secure mà vẫn chạy được trên http://localhost vì trình duyệt và curl coi localhost là an toàn. Lên production phải là HTTPS.
