Package = một thư mục

Đến giờ mọi chương trình chỉ có một file main.go. Dự án thật có hàng trăm file, chia vào các thư mục. Mỗi thư mục là một package.

  • Mọi file .go trong cùng một thư mục thuộc cùng một package, và nhìn thấy nhau hoàn toàn: hàm viết ở file này gọi được ở file kia mà không cần import.
  • Tên package khai báo ở dòng đầu mỗi file (package grade), thường trùng tên thư mục.
  • Muốn dùng package ở thư mục khác thì import nó bằng đường dẫn: tên module (dòng module trong go.mod) + tên thư mục.

Làm theo từng bước để tạo một dự án có hai package.

Bước 1. Tạo thư mục dự án và thư mục con grade:

mkdir sobaitap && cd sobaitap
go mod init github.com/lan/sobaitap   # tên module, dùng làm tiền tố khi import
mkdir grade

Cấu trúc bạn sẽ có sau bước 3:

sobaitap/
├── go.mod                      module github.com/lan/sobaitap
├── main.go                     package main
└── grade/
    ├── grade.go                package grade
    └── grade_test.go           package grade

Bước 2. Tạo file grade/grade.go (nằm trong thư mục grade):

package grade

// Classify: viết HOA chữ đầu → package khác dùng được (exported)
func Classify(score float64) string {
    if score >= 8 {
        return "Giỏi"
    }
    if isPass(score) {
        return "Đạt"
    }
    return "Chưa đạt"
}

// isPass: viết thường → chỉ dùng trong package grade
func isPass(score float64) bool { return score >= 5 }

Bước 3. Tạo file main.go ở thư mục gốc sobaitap:

package main

import (
    "fmt"

    "github.com/lan/sobaitap/grade" // đường dẫn = tên module + "/grade"
)

func main() {
    fmt.Println(grade.Classify(8.5)) // gọi qua tên package: grade.TênHàm
    fmt.Println(grade.Classify(6))
    fmt.Println(grade.Classify(3))
    // grade.isPass(6)               // bỏ // sẽ lỗi: undefined: grade.isPass
}

Bước 4. Chạy ở thư mục gốc sobaitap (nơi có go.mod):

$ go run .
Giỏi
Đạt
Chưa đạt

Bỏ dấu // ở dòng grade.isPass(6) rồi chạy lại: Go báo undefined: grade.isPass, vì tên viết thường không ra được khỏi package. Đó là cách Go làm "private".

Lưu ý grade/grade_test.go trong cây thư mục là file test, bài 10 mới viết. Chưa có nó thì chương trình vẫn chạy.

Thay cho export / không export trong ES module, Go dùng chữ hoa / chữ thường của chính cái tên. Quy tắc áp dụng cho mọi thứ: hàm, kiểu, hằng, biến, trường của struct, method. Vì vậy trường struct viết thường thì encoding/json (một package khác) không nhìn thấy (bài 05).

Đặt tên package

  • Ngắn, chữ thường, một từ, không gạch dưới: grade, auth, postgres.
  • Tên package là một phần khi gọi, nên tránh lặp: http.Server chứ không phải http.HTTPServer, user.New chứ không phải user.NewUser.
  • Tránh package tên utils, common, helpers: chúng thành bãi rác chứa mọi thứ. Đặt tên theo việc nó làm: money, pagination, httpx.

Không được import vòng tròn

Package A import B thì B không được import A (kể cả gián tiếp qua C). Trình biên dịch từ chối ngay. Quy tắc này buộc bạn tổ chức phụ thuộc theo một chiều, từ ngoài vào trong:

[fe] cmd/api (main) :: đọc cấu hình, ghép mọi thứ lại, chạy server [go] internal/http :: handler, middleware, định tuyến [go] internal/service :: nghiệp vụ: quyền, quy tắc, tính toán [db] internal/store :: SQL, Redis [ok] internal/domain :: kiểu dữ liệu và lỗi dùng chung, không import gì của dự án

Khi gặp lỗi import cycle not allowed, gần như luôn là dấu hiệu cần tách phần dùng chung (kiểu dữ liệu, interface) xuống một package ở tầng thấp hơn mà cả hai cùng import.

Thư mục internal/: khoá cửa từ bên ngoài

Package nằm trong thư mục tên internal chỉ được import bởi code nằm trong thư mục cha của internal. Dự án khác không import được, kể cả khi repo công khai. Đây là quy tắc do chính công cụ go thực thi.

Với ứng dụng backend (không phải thư viện cho người khác dùng), đặt gần như mọi thứ trong internal/.

Cấu trúc một dự án API thật

sobaitap/
├── go.mod
├── go.sum
├── cmd/
│   ├── api/main.go          chương trình API
│   └── worker/main.go       chương trình chạy việc nền (cùng repo, khác file chạy)
├── internal/
│   ├── config/              đọc biến môi trường
│   ├── domain/              User, Class, Assignment, các lỗi ErrNotFound...
│   ├── service/             nghiệp vụ
│   ├── store/postgres/      repository dùng SQL
│   ├── httpapi/             handler, middleware, routes
│   └── worker/              xử lý việc trong hàng đợi
├── migrations/              file SQL đổi cấu trúc database
├── Dockerfile
└── Makefile

Trên mạng có repo "golang-standards/project-layout" rất nổi tiếng nhưng nó không phải chuẩn chính thức của đội Go, và quá phức tạp cho đa số dự án. Hướng dẫn chính thức ngắn gọn hơn nằm ở go.dev/doc/modules/layout. Bắt đầu đơn giản, tách package khi file bắt đầu dài và khó tìm.

Cài và quản lý thư viện

go get github.com/jackc/pgx/v5@latest    # thêm / nâng cấp lên bản mới nhất
go get github.com/redis/go-redis/v9@v9.7.0 # chọn đúng phiên bản
go get -u ./...                           # nâng cấp các phụ thuộc (cẩn thận)
go mod tidy                               # thêm cái thiếu, xoá cái không dùng
go list -m all                            # liệt kê mọi module đang dùng
go mod why github.com/x/y                 # vì sao module này có trong dự án

Phiên bản theo semver. Điểm đặc biệt: từ phiên bản chính v2 trở lên, số phiên bản nằm luôn trong đường dẫn import (.../pgx/v5, .../go-redis/v9). Nhờ vậy một dự án có thể dùng v4 và v5 cùng lúc khi đang chuyển dần.

Kiểm tra lỗ hổng bảo mật của các thư viện bạn dùng bằng công cụ chính thức govulncheck:

go install golang.org/x/vuln/cmd/govulncheck@latest
govulncheck ./...

Nó chỉ báo những lỗ hổng mà code của bạn thật sự gọi tới, nên ít báo động giả hơn npm audit nhiều. Nên chạy trong CI (bài 22).

Hàm init: dùng hạn chế

Mỗi package có thể có hàm init(), tự chạy khi package được nạp, trước main. Nó khó test và chạy ngầm, nên chỉ dùng cho việc thật đơn giản. Đọc cấu hình, kết nối database thì làm tường minh trong main.

Đôi khi bạn sẽ thấy import chỉ để chạy init của package đó:

import _ "net/http/pprof" // đăng ký các đường dẫn /debug/pprof vào DefaultServeMux
- Import service vào store, Go sẽ tự xử lý vòng tròn - Chép hàm đó sang store + Xem lại thiết kế: store không nên biết về service. Tách phần dùng chung xuống package thấp hơn (ví dụ domain) ? Go cấm import vòng tròn. Tầng lưu trữ không được phụ thuộc vào tầng nghiệp vụ.

Bài tập

Tách package tiền tệ

Tạo dự án example.com/money có một package riêng tên vnd, chứa:

  • kiểu VND int64, có method String() in dạng 1.234.000đ (dùng lại lời giải "Định dạng tiền Việt" ở bài 02).
  • hàm Parse(s string) (VND, error) đọc chuỗi người dùng gõ như "1.234.000", "49000đ" thành số.

Viết main.go import package vnd và dùng nó. Kết quả mong muốn:

$ go run .
1.234.000đ
49.000đ
lỗi: số tiền không hợp lệ "abc": strconv.ParseInt: parsing "abc": invalid syntax

Gợi ý từng bước

  1. Làm giống ví dụ grade ở trên: mkdir money && cd money, go mod init example.com/money, mkdir vnd.
  2. File vnd/vnd.go bắt đầu bằng package vnd. Tên VND, Parse, String viết hoa để main dùng được. Hàm định dạng phụ đặt tên viết thường (format), chỉ dùng bên trong.
  3. Parse: bỏ khoảng trắng, bỏ chữ đ ở cuối (strings.TrimSuffix), bỏ mọi dấu chấm (strings.ReplaceAll), rồi strconv.ParseInt.
  4. Trong main.go: import "example.com/money/vnd", rồi gọi vnd.Parse(...). Vì VND có method String(), fmt.Println tự in dạng đẹp (bài 06).
Xem lời giải 
money/
├── go.mod          module example.com/money
├── main.go         package main
└── vnd/
    └── vnd.go      package vnd

package vnd

import (
    "fmt"
    "strconv"
    "strings"
)

// VND viết hoa: package khác dùng được
type VND int64

// String giúp fmt.Println(v) in ra dạng 1.234.000đ
func (v VND) String() string {
    return format(int64(v))
}

// Parse nhận "1.234.000", "1234000" hoặc "1.234.000đ"
func Parse(s string) (VND, error) {
    s = strings.TrimSpace(s)          // "  49.000đ " -> "49.000đ"
    s = strings.TrimSuffix(s, "đ")    // "49.000đ"   -> "49.000"
    s = strings.ReplaceAll(s, ".", "") // "49.000"    -> "49000"
    n, err := strconv.ParseInt(s, 10, 64)
    if err != nil {
        return 0, fmt.Errorf("số tiền không hợp lệ %q: %w", s, err)
    }
    return VND(n), nil
}

// format viết thường: chỉ dùng trong package vnd (giống lời giải bài 02)
func format(v int64) string {
    neg := v < 0
    if neg {
        v = -v
    }
    s := strconv.FormatInt(v, 10)
    var sb strings.Builder
    for i, ch := range s {
        if i > 0 && (len(s)-i)%3 == 0 {
            sb.WriteByte('.')
        }
        sb.WriteRune(ch)
    }
    if neg {
        return "-" + sb.String() + "đ"
    }
    return sb.String() + "đ"
}

package main

import (
    "fmt"

    "example.com/money/vnd" // tên module + tên thư mục
)

func main() {
    fmt.Println(vnd.VND(1234000)) // đổi số thành kiểu vnd.VND, Println gọi String()

    price, err := vnd.Parse(" 49.000đ ")
    if err != nil {
        fmt.Println("lỗi:", err)
        return
    }
    fmt.Println(price)

    _, err = vnd.Parse("abc")
    fmt.Println("lỗi:", err)

    // vnd.format(5) // bỏ // sẽ lỗi: undefined: vnd.format (tên viết thường)
}

$ go run .
1.234.000đ
49.000đ
lỗi: số tiền không hợp lệ "abc": strconv.ParseInt: parsing "abc": invalid syntax

Giải thích: bên ngoài package, kiểu được gọi kèm tên package: vnd.VND, vnd.Parse. Chính vì vậy package tên vnd thì hàm nên tên Parse, không cần ParseVND (đọc thành vnd.ParseVND, lặp chữ).

Nếu gặp lỗi package example.com/money/vnd is not in std, kiểm tra dòng module trong go.mod có đúng là example.com/money và bạn đang chạy lệnh ở thư mục chứa go.mod.
