context: huỷ và hạn chót cho cả một chuỗi việc

Người dùng mở trang, request đi vào server, server gọi database và một API bên ngoài. Giữa chừng người dùng đóng tab. Mọi việc phía sau có nên tiếp tục không? Không: tốn tài nguyên cho một response không ai nhận.

context.Context là cách Go truyền tín hiệu huỷ, hạn chót và một ít dữ liệu đi theo request xuyên qua mọi tầng.

[fe] Client đóng tab / hoặc quá 5 giây -> r.Context() bị huỷ [go] Handler / ctx -> truyền ctx xuống [go] Service / ctx -> truyền ctx xuống [db] Postgres / pgx huỷ câu truy vấn đang chạy

Giống AbortController: bạn tạo controller.signal, truyền vào fetch(url, { signal }), gọi controller.abort() để huỷ. Trong Go, ctx đóng vai signal và được truyền vào mọi hàm có I/O.

Quy ước bắt buộc

  • ctx context.Context là tham số đầu tiên của mọi hàm có gọi mạng, database, hoặc chạy lâu.
  • Không lưu ctx vào trong struct. Truyền nó qua tham số.
  • Trong HTTP handler, lấy ctx từ r.Context(): nó tự bị huỷ khi client ngắt kết nối.
  • Chỉ dùng context.Background() ở điểm khởi đầu: hàm main, test, việc nền.

Đặt thời hạn

func (s *Service) Quote(ctx context.Context, id int64) (Price, error) {
    // Gọi dịch vụ tỷ giá bên ngoài, nhưng không chờ quá 2 giây
    ctx, cancel := context.WithTimeout(ctx, 2*time.Second)
    defer cancel() // LUÔN gọi cancel để giải phóng bộ đếm giờ, kể cả khi xong sớm

    rate, err := s.fx.Rate(ctx, "USD", "VND")
    if err != nil {
        if errors.Is(err, context.DeadlineExceeded) {
            return Price{}, fmt.Errorf("dịch vụ tỷ giá quá chậm: %w", err)
        }
        return Price{}, err
    }
    // ...
}

Hạn chót lồng nhau: nếu request gốc còn 1 giây mà bạn đặt WithTimeout(ctx, 2*time.Second), ctx con vẫn hết hạn sau 1 giây. Context con không bao giờ sống lâu hơn context cha.

Tự kiểm tra ctx trong việc chạy lâu

func exportCSV(ctx context.Context, w io.Writer, rows []Row) error {
    for i, r := range rows {
        if i%1000 == 0 { // thỉnh thoảng kiểm tra xem đã bị huỷ chưa
            if err := ctx.Err(); err != nil {
                return err
            }
        }
        writeRow(w, r)
    }
    return nil
}

Giá trị đi theo request

type ctxKey string // kiểu riêng, tránh trùng khoá với package khác

const requestIDKey ctxKey = "request_id"

func WithRequestID(ctx context.Context, id string) context.Context {
    return context.WithValue(ctx, requestIDKey, id)
}

func RequestID(ctx context.Context) string {
    id, _ := ctx.Value(requestIDKey).(string)
    return id
}

Chỉ đặt vào context những thứ thuộc về request: request id, thông tin người dùng đã xác thực, trace id. Không dùng context để truyền tham số tuỳ chọn hay phụ thuộc (database, logger cấu hình): như vậy hàm có tham số ẩn, rất khó đọc và test.

Kiểm thử: có sẵn trong Go

Không cần cài Jest. File test nằm cạnh file code, tên kết thúc bằng _test.go, hàm test bắt đầu bằng Test:

package grade

import "testing"

func TestClassify(t *testing.T) {
    got := Classify(8.5)
    if got != "Giỏi" {
        t.Errorf("Classify(8.5) = %q, muốn %q", got, "Giỏi")
    }
}

go test ./...                 # chạy mọi test
go test ./grade -run Classify # chỉ chạy test có tên khớp
go test -v ./...              # in chi tiết
go test -race -cover ./...    # kèm phát hiện race và độ phủ

t.Errorf báo lỗi nhưng chạy tiếp, t.Fatalf báo lỗi và dừng test đó ngay (dùng khi các bước sau vô nghĩa nếu bước này hỏng).

Test dạng bảng: phong cách chuẩn của Go

Thay vì viết 10 hàm test gần giống nhau, liệt kê các trường hợp trong một bảng rồi chạy vòng lặp:

func TestClassify(t *testing.T) {
    tests := []struct {
        name  string
        score float64
        want  string
    }{
        {"giỏi", 8.5, "Giỏi"},
        {"vừa đủ giỏi", 8, "Giỏi"},
        {"đạt", 6, "Đạt"},
        {"biên dưới đạt", 5, "Đạt"},
        {"chưa đạt", 4.9, "Chưa đạt"},
        {"điểm 0", 0, "Chưa đạt"},
    }
    for _, tc := range tests {
        t.Run(tc.name, func(t *testing.T) {
            if got := Classify(tc.score); got != tc.want {
                t.Errorf("Classify(%v) = %q, muốn %q", tc.score, got, tc.want)
            }
        })
    }
}

Mẹo chọn trường hợp test: trường hợp bình thường, đúng ở biên (8 và 7.99, 5 và 4.99), giá trị rỗng / 0 / âm, và dữ liệu sai. Lỗi thường nằm ở biên.

Test có database thật

Fake (bài 06) phù hợp để test nghiệp vụ. Nhưng câu SQL thì phải test với database thật: fake không biết câu SQL của bạn sai cú pháp hay thiếu index. Hai cách phổ biến:

  • Chạy Postgres bằng Docker trong CI, mỗi test tạo schema riêng hoặc bọc trong một transaction rồi rollback.
  • Thư viện testcontainers-go: test tự bật container Postgres, xong tự tắt.

Nhiều đội chạy toàn bộ test API với database thật, mỗi test một database sạch. Chậm hơn fake, nhưng bắt được những lỗi chỉ database thật mới có: ràng buộc UNIQUE, khoá ngoại, trigger.

Test bảng cho hàm phân trang

Viết test dạng bảng cho hàm page ở bài 04: trang đầu, trang giữa, trang cuối thiếu phần tử, trang vượt quá, page = 0, size âm, danh sách rỗng. Chạy với -cover và đọc độ phủ.

Xem lời giải 
func TestPage(t *testing.T) {
    items := []int{1, 2, 3, 4, 5}
    tests := []struct {
        name       string
        items      []int
        page, size int
        want       []int
    }{
        {"trang đầu", items, 1, 2, []int{1, 2}},
        {"trang giữa", items, 2, 2, []int{3, 4}},
        {"trang cuối thiếu", items, 3, 2, []int{5}},
        {"vượt quá", items, 4, 2, []int{}},
        {"page 0", items, 0, 2, []int{}},
        {"size âm", items, 1, -1, []int{}},
        {"rỗng", nil, 1, 10, []int{}},
    }
    for _, tc := range tests {
        t.Run(tc.name, func(t *testing.T) {
            got := page(tc.items, tc.page, tc.size)
            if !slices.Equal(got, tc.want) {
                t.Errorf("page(%d, %d) = %v, muốn %v", tc.page, tc.size, got, tc.want)
            }
        })
    }
}
Hàm có hạn chót

Viết slowSquare(ctx context.Context, n int) (int, error) mất 1 giây để trả kết quả, nhưng dừng ngay và trả ctx.Err() nếu ctx bị huỷ trước. Viết test chứng minh: với timeout 100ms, hàm trả về context.DeadlineExceeded trong chưa tới 200ms.

Xem lời giải 
func slowSquare(ctx context.Context, n int) (int, error) {
    select {
    case <-time.After(time.Second):
        return n * n, nil
    case <-ctx.Done():
        return 0, ctx.Err()
    }
}

func TestSlowSquareTimeout(t *testing.T) {
    ctx, cancel := context.WithTimeout(context.Background(), 100*time.Millisecond)
    defer cancel()
    start := time.Now()
    _, err := slowSquare(ctx, 3)
    if !errors.Is(err, context.DeadlineExceeded) {
        t.Fatalf("err = %v, muốn DeadlineExceeded", err)
    }
    if d := time.Since(start); d > 200*time.Millisecond {
        t.Errorf("mất %v, quá lâu", d)
    }
}
