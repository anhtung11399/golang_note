Interface, embedding và generics

Interface ngầm định (không cần implements), cách Go dùng interface để thay thế kế thừa, và generics cơ bản.

Học xong bài này bạn sẽ:
  • Định nghĩa và dùng interface nhỏ
  • Hiểu "nhận interface, trả struct"
  • Viết hàm generic đơn giản

#Interface: mô tả hành vi, không cần "implements"

Interface trong Go là một danh sách method. Kiểu nào có đủ các method đó thì tự động thoả interface, không cần viết implements.

Ví dụ đời thường: hệ thống cần nhắc phụ huynh khi con chưa nộp bài. Nhắc bằng email hay bằng thông báo đẩy (push) thì hàm nhắc không cần quan tâm, miễn là "thứ đó gửi được tin".

Go
package main

import "fmt"

// Interface: "thứ gì có method Notify(userID, msg) error thì là một Notifier"
type Notifier interface {
    Notify(userID int64, msg string) error
}

// Kiểu thứ nhất: gửi email
type EmailNotifier struct {
    from string
}

func (e *EmailNotifier) Notify(userID int64, msg string) error {
    fmt.Printf("[email từ %s] gửi người dùng %d: %s\n", e.from, userID, msg)
    return nil
}

// Kiểu thứ hai: gửi push. Không có dòng nào nói "PushNotifier implements Notifier"
type PushNotifier struct{}

func (p *PushNotifier) Notify(userID int64, msg string) error {
    fmt.Printf("[push] gửi người dùng %d: %s\n", userID, msg)
    return nil
}

// Hàm này nhận BẤT KỲ Notifier nào, không biết và không cần biết đang gửi bằng gì
func remindHomework(n Notifier, userID int64) error {
    return n.Notify(userID, "Con chưa nộp bài Toán hôm nay")
}

func main() {
    remindHomework(&EmailNotifier{from: "no-reply@app.vn"}, 42)
    remindHomework(&PushNotifier{}, 42)
}
Terminal — kết quả khi chạy
[email từ no-reply@app.vn] gửi người dùng 42: Con chưa nộp bài Toán hôm nay
[push] gửi người dùng 42: Con chưa nộp bài Toán hôm nay

Đọc chương trình: *EmailNotifier và *PushNotifier đều có method Notify với đúng tham số và kiểu trả về như interface yêu cầu, nên cả hai truyền được vào remindHomework. Thử đổi tên method của PushNotifier thành Send rồi chạy: trình biên dịch báo *PushNotifier does not implement Notifier (missing method Notify).

Các method dùng receiver con trỏ (*EmailNotifier), nên phải truyền con trỏ &EmailNotifier{...}. Truyền EmailNotifier{...} (không có &) sẽ bị báo lỗi tương tự.

Rất giống TypeScript: TS cũng kiểm tra theo cấu trúc (structural typing), một object có đủ thuộc tính là thoả interface. Khác biệt: trong Go chỉ tính method, không tính trường dữ liệu.

Trong code thật, Notify sẽ nhận thêm tham số đầu tiên ctx context.Context để huỷ được khi request bị huỷ (bài 10). Ở đây bỏ đi cho gọn.

#Interface nhỏ là interface tốt

Thư viện chuẩn của Go đầy những interface chỉ có một method. Hai cái nổi tiếng nhất, nằm trong package io:

Go · trích đoạn
type Reader interface {
    Read(p []byte) (n int, err error) // đọc dữ liệu vào p, trả về số byte đọc được
}
type Writer interface {
    Write(p []byte) (n int, err error) // ghi dữ liệu p ra đâu đó
}

Vì chỉ cần một method, rất nhiều thứ là io.Reader: file, body của HTTP request, kết nối mạng, chuỗi trong bộ nhớ, dữ liệu giải nén... Một hàm nhận io.Reader làm việc được với tất cả.

Go
package main

import (
    "encoding/json"
    "fmt"
    "io"
    "strings"
)

type User struct {
    Name string `json:"name"`
}

// Hàm này đọc JSON từ BẤT KỲ nguồn nào có method Read
func decodeUser(r io.Reader) (User, error) {
    var u User
    err := json.NewDecoder(r).Decode(&u) // đọc từ r, ghi kết quả vào u
    return u, err
}

func main() {
    // strings.NewReader biến một chuỗi thành io.Reader: rất tiện để thử và để test
    u, err := decodeUser(strings.NewReader(`{"name":"An"}`))
    fmt.Println(u.Name, err)

    // Trong HTTP server bạn sẽ gọi decodeUser(r.Body), với file: decodeUser(f).
    // Cùng một hàm, không sửa dòng nào.
}
Terminal — kết quả khi chạy
An <nil>

Một interface quen thuộc khác là error: bất kỳ kiểu nào có method Error() string đều là lỗi (bài 07). Và fmt.Stringer: kiểu nào có method String() string thì fmt.Println dùng nó để in:

Go
package main

import "fmt"

type Money int64

// Có method String() string nên Money thoả fmt.Stringer
func (m Money) String() string {
    return fmt.Sprintf("%dđ", int64(m))
}

func main() {
    var price Money = 49000
    fmt.Println(price) // Println thấy price có String() nên gọi nó
}
Terminal — kết quả khi chạy
49000đ

#Interface giúp tách lớp và viết test

Đây là lý do thực tế nhất bạn dùng interface ở backend. Lớp nghiệp vụ (service) không gọi thẳng Postgres mà gọi qua một interface. Lúc chạy thật truyền vào bản Postgres, lúc test truyền vào bản giả lưu trong bộ nhớ.

Chương trình dưới chạy được ngay, không cần database: nó dùng bản giả memStore. Khi có database (bài 15), bạn viết thêm PostgresStore có cùng hai method, và HomeworkService không phải sửa dòng nào.

Go
package main

import (
    "errors"
    "fmt"
)

type Assignment struct {
    ID      int64
    ClassID int64
    Title   string
}

var ErrNotFound = errors.New("không tìm thấy")

// 1. Interface đặt ở nơi DÙNG nó (service), chỉ gồm các method service cần
type AssignmentStore interface {
    Get(id int64) (Assignment, error)
    ListByClass(classID int64) ([]Assignment, error)
}

// 2. Service chỉ biết interface, không biết dữ liệu nằm ở đâu
type HomeworkService struct {
    store AssignmentStore
}

func NewHomeworkService(s AssignmentStore) *HomeworkService {
    return &HomeworkService{store: s}
}

func (h *HomeworkService) CountForClass(classID int64) (int, error) {
    list, err := h.store.ListByClass(classID)
    if err != nil {
        return 0, err
    }
    return len(list), nil
}

// 3. Bản giả lưu trong map: dùng khi test, hoặc khi chưa có database
type memStore struct {
    items map[int64]Assignment
}

func (m *memStore) Get(id int64) (Assignment, error) {
    a, ok := m.items[id]
    if !ok {
        return Assignment{}, ErrNotFound
    }
    return a, nil
}

func (m *memStore) ListByClass(classID int64) ([]Assignment, error) {
    var out []Assignment
    for _, a := range m.items {
        if a.ClassID == classID {
            out = append(out, a)
        }
    }
    return out, nil
}

func main() {
    store := &memStore{items: map[int64]Assignment{
        1: {ID: 1, ClassID: 5, Title: "Toán trang 12"},
        2: {ID: 2, ClassID: 5, Title: "Văn: tả cây"},
        3: {ID: 3, ClassID: 6, Title: "Anh unit 3"},
    }}
    svc := NewHomeworkService(store) // truyền bản giả vào chỗ cần AssignmentStore

    n, _ := svc.CountForClass(5)
    fmt.Println("lớp 5 có", n, "bài")

    _, err := store.Get(99)
    fmt.Println(err)
}
Terminal — kết quả khi chạy
lớp 5 có 2 bài
không tìm thấy

Câu thần chú của dân Go: "Accept interfaces, return structs" (nhận interface, trả về struct cụ thể). Và định nghĩa interface ở phía dùng, không phải phía cài đặt. PostgresStore có thể có 30 method, nhưng mỗi service chỉ khai báo interface 2, 3 method nó thật sự cần. Đừng tạo interface khi chỉ có một cài đặt và không cần test thay thế: Go không phải Java.

Kiểm tra lúc biên dịch rằng một kiểu thoả interface

Go · trích đoạn
// Dòng này không chạy gì cả. Nó chỉ để trình biên dịch báo lỗi ngay
// nếu *memStore thiếu method nào của AssignmentStore
var _ AssignmentStore = (*memStore)(nil)

Đặt dòng này ở cấp file (ngoài mọi hàm), ngay dưới khai báo kiểu. Bạn sẽ thấy nó rất nhiều trong code Go thật.

#any, type assertion và type switch

any (tên khác của interface{}) là interface không có method nào, nên mọi giá trị đều thoả. Giống unknown trong TypeScript: muốn dùng thì phải kiểm tra kiểu trước.

Go
package main

import "fmt"

func describe(v any) { // nhận giá trị kiểu gì cũng được
    // type switch: rẽ nhánh theo KIỂU thật của v. x có kiểu tương ứng trong từng case
    switch x := v.(type) {
    case string:
        fmt.Println("chuỗi dài", len(x)) // ở đây x là string
    case int:
        fmt.Println("số nguyên", x*2) // ở đây x là int, nhân được
    case nil:
        fmt.Println("nil")
    default:
        fmt.Printf("kiểu khác: %T\n", x)
    }
}

func main() {
    describe("xin chào")
    describe(21)
    describe(nil)
    describe(3.14)

    var v any = "xin chào"
    s, ok := v.(string) // type assertion có kiểm tra: "v có phải string không?"
    fmt.Println(s, ok)
    n, ok := v.(int) // không phải int: n = 0, ok = false, không lỗi
    fmt.Println(n, ok)
    // v.(int) mà KHÔNG nhận ok thì sai kiểu là panic. Luôn dùng dạng có ok
}
Terminal — kết quả khi chạy
chuỗi dài 9
số nguyên 42
nil
kiểu khác: float64
xin chào true
0 false

len("xin chào") là 9 chứ không phải 8, vì chữ à chiếm 2 byte (bài 02).

Hạn chế dùng any trong code nghiệp vụ, giống như hạn chế any trong TypeScript. Nơi hợp lý để gặp nó: đọc JSON không biết trước cấu trúc (map[string]any), log, và các thư viện chung.

Cạm bẫy: interface chứa con trỏ nil thì không nil

Một giá trị interface gồm hai phần: kiểu và giá trị. Nó chỉ bằng nil khi cả hai đều trống.

Go
package main

import "fmt"

type MyErr struct{}

func (*MyErr) Error() string { return "lỗi" }

// SAI: trả về một biến con trỏ kiểu cụ thể, dù giá trị là nil
func checkBad() error {
    var e *MyErr = nil
    return e // interface error lúc này: kiểu = *MyErr, giá trị = nil -> KHÔNG phải nil
}

// ĐÚNG: không có lỗi thì trả thẳng nil
func checkGood() error {
    return nil
}

func main() {
    if err := checkBad(); err != nil {
        fmt.Println("checkBad: có lỗi!") // dòng này CHẠY, dù bạn tưởng không có lỗi
    }
    if err := checkGood(); err != nil {
        fmt.Println("checkGood: có lỗi!")
    } else {
        fmt.Println("checkGood: không lỗi")
    }
}
Terminal — kết quả khi chạy
checkBad: có lỗi!
checkGood: không lỗi

#Embedding: ghép thay vì kế thừa

Go không có kế thừa (extends). Muốn dùng lại, bạn nhúng một kiểu vào kiểu khác: viết tên kiểu mà không đặt tên trường. Trường và method của kiểu được nhúng được "đưa lên" kiểu ngoài.

Go
package main

import (
    "fmt"
    "time"
)

type Timestamps struct {
    CreatedAt time.Time
    UpdatedAt time.Time
}

func (t *Timestamps) Touch() {
    t.UpdatedAt = time.Date(2026, 11, 3, 9, 0, 0, 0, time.UTC) // code thật dùng time.Now()
}

type Class struct {
    Timestamps // nhúng: chỉ có tên kiểu, không có tên trường
    ID         int64
    Name       string
}

func main() {
    c := Class{Name: "5A"}
    c.Touch() // gọi method của Timestamps như thể của Class
    fmt.Println(c.Name, c.UpdatedAt.Format("02/01/2006 15:04"))
    // c.UpdatedAt là cách viết tắt của c.Timestamps.UpdatedAt
}
Terminal — kết quả khi chạy
5A 03/11/2026 09:00

Format("02/01/2006 15:04"): Go định dạng ngày bằng một ngày mẫu cố định (2 tháng 1 năm 2006, 15:04), thay vì DD/MM/YYYY. Lạ, nhưng quen nhanh.

Interface cũng nhúng được vào nhau:

Go · trích đoạn
type ReadWriter interface {
    io.Reader // có đủ method của Reader
    io.Writer // và của Writer
}

Giống React chuyển từ class component kế thừa sang ghép component và hook: "composition over inheritance". Go chỉ cho bạn con đường ghép.

#Generics (từ Go 1.18)

Generics cho phép viết hàm / kiểu dùng được cho nhiều kiểu dữ liệu, giống function f<T>(x: T) trong TypeScript. Go dùng ngoặc vuông [T any] thay cho ngoặc nhọn <T>.

Go
package main

import (
    "cmp"
    "fmt"
)

// TS: function Map<T, U>(items: T[], f: (x: T) => U): U[]
func Map[T, U any](items []T, f func(T) U) []U {
    out := make([]U, 0, len(items))
    for _, it := range items {
        out = append(out, f(it))
    }
    return out
}

// cmp.Ordered là RÀNG BUỘC: T phải là kiểu so sánh lớn nhỏ được (số, chuỗi)
func MaxOf[T cmp.Ordered](items []T) (T, bool) {
    var zero T // zero value của T: 0 với số, "" với chuỗi
    if len(items) == 0 {
        return zero, false
    }
    m := items[0]
    for _, x := range items[1:] {
        if x > m { // được dùng > vì T bị ràng buộc là Ordered
            m = x
        }
    }
    return m, true
}

// Kiểu generic: response phân trang dùng chung cho mọi loại dữ liệu
type Page[T any] struct {
    Items []T
    Total int
}

type User struct{ Name string }

func main() {
    users := []User{{"An"}, {"Bình"}}
    names := Map(users, func(u User) string { return u.Name }) // Go tự suy ra T = User, U = string
    fmt.Println(names)

    fmt.Println(MaxOf([]int{3, 9, 4}))
    fmt.Println(MaxOf([]string{"lê", "an", "minh"}))
    fmt.Println(MaxOf([]float64{}))

    p := Page[User]{Items: users, Total: 2} // tạo kiểu generic thì ghi rõ T
    fmt.Printf("%+v\n", p)
}
Terminal — kết quả khi chạy
[An Bình]
9 true
minh true
0 false
{Items:[{Name:An} {Name:Bình}] Total:2}

fmt.Println(MaxOf(...)) in cả hai giá trị trả về. "minh" lớn nhất vì chuỗi so sánh theo thứ tự chữ cái.

Thư viện chuẩn đã có sẵn nhiều hàm generic: package slices (Sort, Contains, Index, Max...), maps, cmp. Dùng generics khi bạn sắp chép cùng một đoạn code cho nhiều kiểu. Đừng dùng chỉ vì nó có: interface thường là lựa chọn đơn giản hơn khi cái bạn cần là hành vi khác nhau.

Câu hỏi nhanh. Kiểu *FileLogger có method Write(p []byte) (int, error). Cần làm gì để truyền nó vào hàm nhận io.Writer?

Interface trong Go được thoả một cách ngầm định: có đủ method với đúng chữ ký là đủ.

#Bài tập

Thông báo nhiều kênh

Dùng lại Notifier ở đầu bài. Viết kiểu MultiNotifier chứa một danh sách Notifier, và bản thân nó cũng là một Notifier: gọi lần lượt từng kênh, kênh nào lỗi thì vẫn gửi tiếp các kênh khác, cuối cùng trả về tất cả lỗi gộp lại.

Thử với ba kênh: email (thành công), SMS (luôn lỗi "hết tiền"), push (thành công). Kết quả mong muốn:

Terminal — kết quả khi chạy
[email] 42: Con chưa nộp bài
[push] 42: Con chưa nộp bài
lỗi: sms: hết tiền

Gợi ý từng bước

  1. Một kiểu có thể dựa trên slice: type MultiNotifier []Notifier. Nó là slice, nhưng gắn method được.
  2. Viết method func (m MultiNotifier) Notify(userID int64, msg string) error. Có đúng chữ ký như interface, nên MultiNotifier tự động là Notifier.
  3. Trong method: duyệt m, gọi Notify của từng kênh. Lỗi thì gom vào một slice []error, không return sớm.
  4. Cuối cùng return errors.Join(errs...): gộp nhiều lỗi thành một. Không có lỗi nào thì nó trả nil.
Xem lời giải
main.go
package main

import (
    "errors"
    "fmt"
)

type Notifier interface {
    Notify(userID int64, msg string) error
}

// Ba kênh để thử
type Email struct{}

func (Email) Notify(id int64, msg string) error {
    fmt.Printf("[email] %d: %s\n", id, msg)
    return nil
}

type SMS struct{}

func (SMS) Notify(id int64, msg string) error {
    return errors.New("sms: hết tiền") // giả lập kênh luôn lỗi
}

type Push struct{}

func (Push) Notify(id int64, msg string) error {
    fmt.Printf("[push] %d: %s\n", id, msg)
    return nil
}

// MultiNotifier là một slice các Notifier...
type MultiNotifier []Notifier

// ...và cũng là một Notifier, vì có method Notify đúng chữ ký
func (m MultiNotifier) Notify(userID int64, msg string) error {
    var errs []error
    for _, n := range m {
        if err := n.Notify(userID, msg); err != nil {
            errs = append(errs, err) // ghi nhận lỗi rồi gửi tiếp kênh sau
        }
    }
    return errors.Join(errs...) // không có lỗi nào thì trả về nil
}

// Trình biên dịch kiểm tra giúp: MultiNotifier có thoả Notifier không
var _ Notifier = MultiNotifier(nil)

func main() {
    all := MultiNotifier{Email{}, SMS{}, Push{}}
    if err := all.Notify(42, "Con chưa nộp bài"); err != nil {
        fmt.Println("lỗi:", err)
    }
}
Terminal — kết quả khi chạy
[email] 42: Con chưa nộp bài

Giải thích: lỗi của SMS không chặn push. Ở đây các method dùng receiver giá trị (func (Email) Notify, không đặt tên receiver vì không dùng tới), nên truyền Email{} không cần &. Đây là mẫu composite: bên gọi chỉ thấy một Notifier, không biết bên trong có mấy kênh.

Hàm GroupBy generic

Viết GroupBy[T any, K comparable](items []T, key func(T) K) map[K][]T: nhận một danh sách và một hàm lấy "khoá" của từng phần tử, trả về map gom các phần tử cùng khoá. Dùng nó để gom bài tập theo môn học. Kết quả mong muốn:

Terminal — kết quả khi chạy
Toán: [Trang 12 Trang 15]
Văn: [Tả cây]

Gợi ý từng bước

  1. Tương tự lodash.groupBy(items, x => x.subject).
  2. Tạo out := make(map[K][]T). Duyệt items, tính k := key(it), rồi out[k] = append(out[k], it). Khoá chưa có thì out[k] là slice nil, append vào nil vẫn chạy.
  3. In kết quả theo thứ tự cố định (map duyệt ngẫu nhiên): lấy khoá và sắp xếp như bài 04.
Xem lời giải
main.go
package main

import (
    "fmt"
    "maps"
    "slices"
)

// T: kiểu phần tử, bất kỳ. K: kiểu khoá, phải "comparable" (so sánh được bằng ==) mới làm khoá map được
func GroupBy[T any, K comparable](items []T, key func(T) K) map[K][]T {
    out := make(map[K][]T)
    for _, it := range items {
        k := key(it)
        out[k] = append(out[k], it)
    }
    return out
}

type Assignment struct {
    Subject string
    Title   string
}

func main() {
    list := []Assignment{
        {"Toán", "Trang 12"},
        {"Văn", "Tả cây"},
        {"Toán", "Trang 15"},
    }

    bySubject := GroupBy(list, func(a Assignment) string { return a.Subject })

    for _, subject := range slices.Sorted(maps.Keys(bySubject)) {
        titles := []string{}
        for _, a := range bySubject[subject] {
            titles = append(titles, a.Title)
        }
        fmt.Printf("%s: %v\n", subject, titles)
    }
}
Terminal — kết quả khi chạy
Toán: [Trang 12 Trang 15]
Văn: [Tả cây]

comparable là ràng buộc có sẵn: kiểu dùng được với ==, điều kiện để làm khoá của map. Struct Assignment trong ví dụ được tạo không ghi tên trường ({"Toán", "Trang 12"}): được phép, các giá trị điền theo thứ tự khai báo, nhưng code thật nên ghi tên trường cho dễ đọc.
