Package, module và cấu trúc dự án

Chia code thành package, quy tắc viết hoa để public, cài thư viện, cấu trúc thư mục dự án Go thực tế.

Học xong bài này bạn sẽ:
  • Tổ chức code thành nhiều package
  • Cài và quản lý thư viện bằng go get
  • Biết cấu trúc cmd/ và internal/

#Package = một thư mục

Đến giờ mọi chương trình chỉ có một file main.go. Dự án thật có hàng trăm file, chia vào các thư mục. Mỗi thư mục là một package.

  • Mọi file .go trong cùng một thư mục thuộc cùng một package, và nhìn thấy nhau hoàn toàn: hàm viết ở file này gọi được ở file kia mà không cần import.
  • Tên package khai báo ở dòng đầu mỗi file (package grade), thường trùng tên thư mục.
  • Muốn dùng package ở thư mục khác thì import nó bằng đường dẫn: tên module (dòng module trong go.mod) + tên thư mục.

Làm theo từng bước để tạo một dự án có hai package.

Bước 1. Tạo thư mục dự án và thư mục con grade:

Terminal
mkdir sobaitap && cd sobaitap
go mod init github.com/lan/sobaitap   # tên module, dùng làm tiền tố khi import
mkdir grade

Cấu trúc bạn sẽ có sau bước 3:

Cấu trúc
sobaitap/
├── go.mod                      module github.com/lan/sobaitap
├── main.go                     package main
└── grade/
    ├── grade.go                package grade
    └── grade_test.go           package grade

Bước 2. Tạo file grade/grade.go (nằm trong thư mục grade):

grade/grade.go
package grade

// Classify: viết HOA chữ đầu → package khác dùng được (exported)
func Classify(score float64) string {
    if score >= 8 {
        return "Giỏi"
    }
    if isPass(score) {
        return "Đạt"
    }
    return "Chưa đạt"
}

// isPass: viết thường → chỉ dùng trong package grade
func isPass(score float64) bool { return score >= 5 }

Bước 3. Tạo file main.go ở thư mục gốc sobaitap:

main.go
package main

import (
    "fmt"

    "github.com/lan/sobaitap/grade" // đường dẫn = tên module + "/grade"
)

func main() {
    fmt.Println(grade.Classify(8.5)) // gọi qua tên package: grade.TênHàm
    fmt.Println(grade.Classify(6))
    fmt.Println(grade.Classify(3))
    // grade.isPass(6)               // bỏ // sẽ lỗi: undefined: grade.isPass
}

Bước 4. Chạy ở thư mục gốc sobaitap (nơi có go.mod):

Terminal — kết quả khi chạy
$ go run .
Giỏi
Đạt
Chưa đạt

Bỏ dấu // ở dòng grade.isPass(6) rồi chạy lại: Go báo undefined: grade.isPass, vì tên viết thường không ra được khỏi package. Đó là cách Go làm "private".

Lưu ý grade/grade_test.go trong cây thư mục là file test, bài 10 mới viết. Chưa có nó thì chương trình vẫn chạy.

Thay cho export / không export trong ES module, Go dùng chữ hoa / chữ thường của chính cái tên. Quy tắc áp dụng cho mọi thứ: hàm, kiểu, hằng, biến, trường của struct, method. Vì vậy trường struct viết thường thì encoding/json (một package khác) không nhìn thấy (bài 5).

#Đặt tên package

  • Ngắn, chữ thường, một từ, không gạch dưới: grade, auth, postgres.
  • Tên package là một phần khi gọi, nên tránh lặp: http.Server chứ không phải http.HTTPServer, user.New chứ không phải user.NewUser.
  • Tránh package tên utils, common, helpers: chúng thành bãi rác chứa mọi thứ. Đặt tên theo việc nó làm: money, pagination, httpx.

#Không được import vòng tròn

Package A import B thì B không được import A (kể cả gián tiếp qua C). Trình biên dịch từ chối ngay. Quy tắc này buộc bạn tổ chức phụ thuộc theo một chiều, từ ngoài vào trong:

Khi gặp lỗi import cycle not allowed, gần như luôn là dấu hiệu cần tách phần dùng chung (kiểu dữ liệu, interface) xuống một package ở tầng thấp hơn mà cả hai cùng import.

#Thư mục internal/: khoá cửa từ bên ngoài

Package nằm trong thư mục tên internal chỉ được import bởi code nằm trong thư mục cha của internal. Dự án khác không import được, kể cả khi repo công khai. Đây là quy tắc do chính công cụ go thực thi.

Với ứng dụng backend (không phải thư viện cho người khác dùng), đặt gần như mọi thứ trong internal/.

#Cấu trúc một dự án API thật

Cấu trúc gợi ý (dùng ở dự án cuối, bài 32)

Trên mạng có repo "golang-standards/project-layout" rất nổi tiếng nhưng nó không phải chuẩn chính thức của đội Go, và quá phức tạp cho đa số dự án. Hướng dẫn chính thức ngắn gọn hơn nằm ở go.dev/doc/modules/layout. Bắt đầu đơn giản, tách package khi file bắt đầu dài và khó tìm.

#Cài và quản lý thư viện

Terminal
go get github.com/jackc/pgx/v5@latest    # thêm / nâng cấp lên bản mới nhất
go get github.com/redis/go-redis/v9@v9.7.0 # chọn đúng phiên bản
go get -u ./...                           # nâng cấp các phụ thuộc (cẩn thận)
go mod tidy                               # thêm cái thiếu, xoá cái không dùng
go list -m all                            # liệt kê mọi module đang dùng
go mod why github.com/x/y                 # vì sao module này có trong dự án

Phiên bản theo semver. Điểm đặc biệt: từ phiên bản chính v2 trở lên, số phiên bản nằm luôn trong đường dẫn import (.../pgx/v5, .../go-redis/v9). Nhờ vậy một dự án có thể dùng v4 và v5 cùng lúc khi đang chuyển dần.

Kiểm tra lỗ hổng bảo mật của các thư viện bạn dùng bằng công cụ chính thức govulncheck:

Terminal
go install golang.org/x/vuln/cmd/govulncheck@latest
govulncheck ./...

Nó chỉ báo những lỗ hổng mà code của bạn thật sự gọi tới, nên ít báo động giả hơn npm audit nhiều. Nên chạy trong CI (bài 29).

#go get tải thư viện từ đâu

Khác npm (một registry trung tâm), module Go có tên là đường dẫn repo (github.com/jackc/pgx/v5). Nhưng mặc định go không tải thẳng từ GitHub mà qua module proxy của Google, và kiểm tra mã băm với checksum database, để không ai tráo được code của một phiên bản đã phát hành.

Biến môi trườngDùng khi
GOPROXY=https://proxy.golang.org,directmặc định: hỏi proxy trước, không có thì tải thẳng từ repo
GOPRIVATE=gitlab.congty.vn/*module nội bộ của công ty: không qua proxy công cộng, không gửi tên lên sum.golang.org
GOFLAGS=-mod=modcho phép tự sửa go.mod khi build (thường để mặc định)

Repo riêng trên GitLab / GitHub cần thêm quyền cho git, ví dụ git config --global url."git@gitlab.congty.vn:".insteadOf "https://gitlab.congty.vn/" để tải bằng SSH key.

So với npm: go.mod giống package.json, go.sum giống package-lock.json nhưng chỉ chứa mã băm. Go chọn phiên bản theo cách "phiên bản tối thiểu thoả mãn" (MVS): nếu không ai yêu cầu bản mới hơn, Go không tự nâng. Không có thư mục node_modules trong dự án, mọi module nằm chung ở ~/go/pkg/mod và không bao giờ bị sửa.

#replace và go.work: sửa thư viện, làm nhiều module

Đang sửa lỗi trong một thư viện và muốn dự án dùng bản trên máy:

go.mod
module sobaitap

go 1.25

require github.com/congty/thuvien v1.3.0

replace github.com/congty/thuvien => ../thuvien   // dùng thư mục trên máy thay cho bản đã phát hành

Nhớ xoá dòng replace trước khi commit, vì máy khác không có ../thuvien. Cách gọn hơn từ Go 1.18 là workspace: file go.work (không commit) gom nhiều module trên máy lại.

Terminal
go work init ./sobaitap ./thuvien   # tạo go.work
go work use ./thuvien-khac          # thêm module

Một repo có nhiều module (monorepo: api/, worker/, shared/ mỗi thư mục một go.mod) cũng dùng go.work. Nhưng lời khuyên chung: một repo một module cho tới khi có lý do rõ ràng, vì nhiều module là nhiều phiên bản phải quản lý.

#Công cụ dự án: go tool, go generate, go:embed

Công cụ phát triển (sqlc, mockgen, oapi-codegen) nên được khoá phiên bản giống thư viện, để mọi người và CI dùng đúng một bản. Từ Go 1.24:

Terminal
go get -tool github.com/sqlc-dev/sqlc/cmd/sqlc@v1.29.0   # ghi vào go.mod, mục tool
go tool sqlc generate                                    # chạy đúng phiên bản đã khoá

go generate chạy các lệnh viết trong chú thích //go:generate. Quy ước: code sinh ra được commit vào git, để người khác build không cần cài công cụ.

Go · trích đoạn
//go:generate go tool sqlc generate
//go:generate go tool mockgen -source=service.go -destination=mock_test.go -package=service

go:embed nhúng file vào trong binary lúc build: migration, mẫu email, file tĩnh của trang quản trị. Deploy chỉ cần một file chạy duy nhất.

Go · trích đoạn
import "embed"

//go:embed migrations/*.sql
var migrations embed.FS

//go:embed templates/welcome.html
var welcomeHTML string // một file → string hoặc []byte

#Build cho máy khác và gắn phiên bản

Go biên dịch chéo bằng hai biến môi trường, không cần cài gì thêm:

Terminal
GOOS=linux GOARCH=amd64 go build -o bin/api-linux ./cmd/api     # máy chủ Linux x86
GOOS=linux GOARCH=arm64 go build -o bin/api-arm ./cmd/api       # máy chủ ARM (AWS Graviton, rẻ hơn)
GOOS=windows GOARCH=amd64 go build -o bin/api.exe ./cmd/api
CGO_ENABLED=0 go build ./cmd/api                                # binary tĩnh, chạy được trong image distroless/scratch

Gắn phiên bản và mã commit vào binary lúc build bằng -ldflags, để endpoint /version hay log khởi động cho biết đang chạy bản nào:

cmd/api/main.go
package main

import (
    "fmt"
    "runtime/debug"
)

var version = "dev" // ghi đè lúc build

func main() {
    commit := "?"
    if info, ok := debug.ReadBuildInfo(); ok { // Go tự ghi thông tin git vào binary
        for _, s := range info.Settings {
            if s.Key == "vcs.revision" && len(s.Value) >= 7 {
                commit = s.Value[:7]
            }
        }
    }
    fmt.Println("phiên bản", version, "commit", commit)
}
Terminal — kết quả minh hoạMô phỏng
$ go build -ldflags "-s -w -X main.version=1.4.3" -o api ./cmd/api && ./api
phiên bản 1.4.3 commit 9f2c1ab

-s -w bỏ thông tin gỡ lỗi, binary nhỏ hơn khoảng 25%. -X main.version=... đặt giá trị cho biến chuỗi version của package main.

Build tag chọn file theo điều kiện. Dòng đầu file //go:build integration nghĩa là file chỉ được biên dịch khi chạy go test -tags=integration (bài 28). Tên file x_linux.go, x_windows.go tự chọn theo hệ điều hành.

#Hàm init: dùng hạn chế

Mỗi package có thể có hàm init(), tự chạy khi package được nạp, trước main. Nó khó test và chạy ngầm, nên chỉ dùng cho việc thật đơn giản. Đọc cấu hình, kết nối database thì làm tường minh trong main.

Đôi khi bạn sẽ thấy import chỉ để chạy init của package đó:

Go · trích đoạn
import _ "net/http/pprof" // đăng ký các đường dẫn /debug/pprof vào DefaultServeMux

Câu hỏi nhanh. Package internal/store cần gọi một hàm trong internal/service, trong khi service đã import store. Cách xử lý đúng?

Go cấm import vòng tròn. Tầng lưu trữ không được phụ thuộc vào tầng nghiệp vụ.

#Bài tập

Tách package tiền tệ

Tạo dự án example.com/money có một package riêng tên vnd, chứa:

  • kiểu VND int64, có method String() in dạng 1.234.000đ (dùng lại lời giải "Định dạng tiền Việt" ở bài 2).
  • hàm Parse(s string) (VND, error) đọc chuỗi người dùng gõ như "1.234.000", "49000đ" thành số.

Viết main.go import package vnd và dùng nó. Kết quả mong muốn:

Terminal — kết quả khi chạy
$ go run .
1.234.000đ
49.000đ
lỗi: số tiền không hợp lệ "abc": strconv.ParseInt: parsing "abc": invalid syntax

Gợi ý từng bước

  1. Làm giống ví dụ grade ở trên: mkdir money && cd money, go mod init example.com/money, mkdir vnd.
  2. File vnd/vnd.go bắt đầu bằng package vnd. Tên VND, Parse, String viết hoa để main dùng được. Hàm định dạng phụ đặt tên viết thường (format), chỉ dùng bên trong.
  3. Parse: bỏ khoảng trắng, bỏ chữ đ ở cuối (strings.TrimSuffix), bỏ mọi dấu chấm (strings.ReplaceAll), rồi strconv.ParseInt.
  4. Trong main.go: import "example.com/money/vnd", rồi gọi vnd.Parse(...). Vì VND có method String(), fmt.Println tự in dạng đẹp (bài 6).
Xem lời giải
Cấu trúc
money/
├── go.mod          module example.com/money
├── main.go         package main
└── vnd/
    └── vnd.go      package vnd
vnd/vnd.go
package vnd

import (
    "fmt"
    "strconv"
    "strings"
)

// VND viết hoa: package khác dùng được
type VND int64

// String giúp fmt.Println(v) in ra dạng 1.234.000đ
func (v VND) String() string {
    return format(int64(v))
}

// Parse nhận "1.234.000", "1234000" hoặc "1.234.000đ"
func Parse(s string) (VND, error) {
    s = strings.TrimSpace(s)          // "  49.000đ " -> "49.000đ"
    s = strings.TrimSuffix(s, "đ")    // "49.000đ"   -> "49.000"
    s = strings.ReplaceAll(s, ".", "") // "49.000"    -> "49000"
    n, err := strconv.ParseInt(s, 10, 64)
    if err != nil {
        return 0, fmt.Errorf("số tiền không hợp lệ %q: %w", s, err)
    }
    return VND(n), nil
}

// format viết thường: chỉ dùng trong package vnd (giống lời giải bài 02)
func format(v int64) string {
    neg := v < 0
    if neg {
        v = -v
    }
    s := strconv.FormatInt(v, 10)
    var sb strings.Builder
    for i, ch := range s {
        if i > 0 && (len(s)-i)%3 == 0 {
            sb.WriteByte('.')
        }
        sb.WriteRune(ch)
    }
    if neg {
        return "-" + sb.String() + "đ"
    }
    return sb.String() + "đ"
}
